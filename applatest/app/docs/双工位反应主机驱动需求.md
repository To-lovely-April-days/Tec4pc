# 双工位反应主机 · 真机驱动需求（定稿）

这台「双工位反应主机」在物理上是**四个独立模块拼起来的一台机器**，
每个模块各占一条串口。上位机把它呈现为**一台设备、两个通道**（工位 A / 工位 B），
现在由仿真驱动 `tec.reactor.rd105` 顶着的那个位置，将来由这个真机驱动顶上——
台面、HMI 手动面板、配方执行、安全监控全都不用改，改的只是数据从哪来。

一条铁规矩不变：**界面上出现的每一个数都得有出处。**
哪路探头没接就发 NaN 不发假数；哪条串口没开就把「没开」写清楚，不糊。

## 1. 硬件拓扑

```
                    ┌─ 工位 A ─────────────┐   ┌─ 工位 B ─────────────┐
                    │ 夹套 Tj-A ← RD105 TC1│   │ 夹套 Tj-B ← RD105 TC2│
                    │ 釜内 Tr-A ← 宇电J7 CH1│  │ 釜内 Tr-B ← 宇电J7 CH2│
                    │ pH-A    ← 宇电J4 CH1 │   │ pH-B    ← 宇电J4 CH2 │
                    │ 热源切换 ← IO8R DO0  │   │ 热源切换 ← IO8R DO1  │
                    └──────────────────────┘   └──────────────────────┘
```

| 模块 | 型号 | 干什么 | 协议 | 串口 |
|---|---|---|---|---|
| TEC 温控器 | 光测未来 RD105（一台带 TC1/TC2 两路） | 两工位夹套控温：TC 探头测 **夹套温度 Tj**，PID 回路闭在夹套上 | RD105 ASCII（TecControl.Core 已 vendored） | 独立一条 |
| 釜内测温 | 宇电 AI-8848GD91J7（热偶/热阻 4 路） | 两工位 **釜内 Tr**（只采集，不控制） | Modbus RTU | 独立一条 |
| pH 采集 | 宇电 AI-8848GD91J4（4~20mA 4 路） | 两工位 **pH**（只采集） | Modbus RTU | 独立一条 |
| IO 模块 | 艾莫迅 JY-MODBUS-IO8R（8DO 继电器 + 8DI 光耦） | 每工位一个热源切换继电器 + 切换反馈 DI | Modbus RTU | 独立一条 |

**串口归属（用户定的）：每台设备的串口写在自己的属性里。**
主机只管自己的两条（RD105、IO8R）；宇电两台的串口分别在「Tr 温度探头
（真机）」「pH 玻璃电极（真机）」两支探头设备的属性里。
**宇电两台可分可合**：分开装各占一条串口（两台地址都留出厂 1 即可）；
拼在同一段导轨上时通讯端子自动并联（手册 §3.3——拼一起就已经在同一条
485 总线上），这时两支探头填同一个口名即共线，由串口池合并成一条链路
（第一个来的定波特率，后来的必须一致）；共线时两台模块地址必须不同
（出厂都是 1，先用面板改一台）。同一台模块的两支探头：同口 + 同地址，
「宇电通道」分别选各自那一路。

**通道映射（拟定，接线定了按实物改配置即可）：**
工位 A = 通道 0 ← RD105 TC1 + 宇电两台的 CH1 + IO8R DO0/DI0；
工位 B = 通道 1 ← RD105 TC2 + 宇电两台的 CH2 + IO8R DO1/DI1。
宇电通道号↔工位的对应做成设备配置项，不写死——现场接线未必按拟定来。

**与台面设备库的对应（用户明确）：** 库里的「Tr 温度探头」「pH 玻璃电极」
在真机上就是宇电两台的物理探头——J7 的一路 = 一支 Tr 探头，J4 的一路 = 一支
pH 电极。台面交互不变：电极/探头插到哪个工位，就是在说「这一路由它量」。
**真机探头是独立设备、自己产数**（与仿真世界同构：仿真 pH 电极也是自己发数）：
探头会话轮询宇电模块上自己那一路（配置项「宇电通道」），把 Tr/pH 发到所绑
通道并以 IScalarSensor 端出去；主机经 IExternalReactorTemp 接住别的会话发的
Tr，用于判到达、E 级紧急程序与 dT——没插 Tr 探头时判到达退回按夹套，如实
降级不冒充。「模拟」勾选框在仿真 ⇄ 真机探头之间换身份，仿真探头不会和
真机探头同时在同一通道上发数。

## 2. 控温与热源切换

### 2.1 两种热源 = 两个系统（0333 / 0336，用户定的）

一路 RD105 只有一个输出，**正负号选系统**：负占空比 → PWM 固态继电器 → 电加热棒（**升温系统**），
正占空比 → H 桥 → TEC（**降温系统**，这台机器 TEC 只能制冷：反向那一极接的就是加热棒的 SSR）。
两个系统都按输出功率大小连续调。冷水机是手动开关，软件不能自动；用户定的（0336）：**冷水机直开**，
反应会放热也会吸热，**控得住就得加热、制冷随时都能出力**。

- **升温系统**：电加热棒。**降温系统**：TEC 制冷。哪只接在线上由 IO8R 的两只继电器定（见下）。
- **「冷水机」已开（缺省）= 双向挡**（0336）：**一个 PID 两边出力**——正给加热棒、负给 TEC 制冷，同一组参数（加热棒那张表，
  负半轴乘该行「加热比」放大给 TEC），过零积分不清、什么都不重置。**继电器跟着 PID 输出的符号走**：同号连续 3 s 才扳一次
  （关输出 → 断一只 → 合一只 → 开输出，一秒钟）。保温段要的功率一直是正的（夹套往冷却水漏热），所以不抖；只在落地、
  放热起来 / 结束这种真要换方向的时候扳。
- **「冷水机」已关 = 升温挡 / 降温挡**（0333）：升温、保温只用加热棒，过了头关加热棒自然凉；降温目标没水不接 TEC，
  两只都断着自然凉，自然凉到了目标交给加热棒维持。
- **「TEC 加热」启用**（不是这台机器）：TEC 反向输出也能加热，目标超过切换阈值才切电加热——原来那套，不分挡。
- **TEC 功率线也经 IO8R 的继电器**（现场电气定的，2026-09-21：DO6 = 工位 A、DO7 = 工位 B，
  闭合 TEC 才有电——从前没人合它，现场「降温没反应」就是这个）。**不常合**（用户定的）：
  开机与不控温时两只都断着；打开温控后只合一只——要制冷合 TEC 功率线、其余合加热棒，双向挡里再跟着功率符号扳；
  TEC 接不上（冷水机关 / 夹套烫）就加热棒那只（冷水机关的降温挡两只都断）。换向先断后通（两只从不同时闭合）；
  停控 / 安全停机两只全断。配置项「TEC 功率继电器」有 / 无（默认有），功率线硬线直连的机器选「无」。
  IO8R 不通时这台既不能制冷也不能加热，所有控温目标拒绝并写明。
- 配置项「冷水机」：**已开（默认，0334）** / 已关。属性栏上改了当拍生效（跟「TEC 加热」同一机制）：在控的路按新规矩重新定挡，
  改成「已关」时正在 TEC 侧的当拍断开功率线。TEC 没有冷却水会干烧，软件看不见水——标「已开」就真开水。

### 2.2 TEC 接入上限（设备配置项）

- 标签「TEC 接入上限」（0336 前叫「电加热切换阈值」，键没变、存过的配置照用），默认 **90 ℃**，**只允许 ≤ 90 往下调，
  不允许调高**——90 是 TEC 模块自身耐温的工程上限，等厂家给出模块热端最高温度再定。
- 「接入滞回」（0336 前叫「回切滞回」），默认 5 K，范围 2~20 K：夹套高过上限断开 TEC 之后，要凉到 上限 − 滞回 才再接。
- 每工位独立判断、独立切换（A、B 各有一个继电器）。「TEC 加热」启用时它兼作「目标高于它才切电加热」的阈值。

### 2.3 定挡与切换判据（0333 / 0336）

「TEC 加热」不启用（这台机器）：

- **下发目标时定挡**：「冷水机」已开 = **双向挡**；已关按方向——目标比当前温度低超过「升降温死区」（默认 2 K）= **降温挡**，
  其余（高于当前、或低不到一个死区）= **升温挡**。当前温度：釜内（串级）目标看新鲜的 Tr，夹套目标 / Tr 不新鲜看 Tj。
  夹套读不到不定挡、一只都不合，采集循环读到了再定。
- **双向挡**：起步按方向合一只（比当前低超过死区合 TEC 功率线，其余合加热棒——保温要的功率是正的）；之后**只看 PID 输出的符号**
  （温控器 PID 方式看读回的占空比）：|功率| ≤ 1 % 不表态，指向另一侧连续 3 s 才扳，扳的时候 PID 不复位。
  蒸回流每拍改跟随目标不按方向重算（Tr 抖动不扳继电器，只看符号）。串级丢了 Tr 的保持期也照旧跟符号（一个 PID 的规矩不设例外：
  夹套设定钳到釜内设定、回路要制冷就接 TEC，不然负半轴写到断着的 TEC 引脚上白攒积分）。
  **夹套 > TEC 接入上限**：TEC 功率线断开、只加热棒出力、功率下限钳到 0（同一组参数只改限幅、不复位、输出不关），
  凉到 上限 − 滞回 再放开；进双向挡那一刻夹套已经高过 上限 − 滞回 也先不接。按段报一次 warn。
- **升温挡**（冷水机已关）→ 加热棒继电器合、TEC 功率线断，回路只加热。**中途温度漂动不换挡**，过了头加热棒收到 0 自然凉，
  绝不接 TEC；「恒温保持」（目标 = 此刻釜温）是升温挡；蒸回流钉死升温挡；保持期不换热源。
- **降温挡**（冷水机已关）→ 没水不接 TEC：两只都断着自然凉，warn 一次「标为已关」（夹套还烫另报 error「本路暂时没有制冷能力」）；
  自然凉到了目标交给加热棒维持（一次交接，不回头），新目标再定挡。0333 那条「TEC 收到 0 够 60 s 才交接」随 0336 撤掉：
  冷水机已开是双向挡，降温挡里 TEC 根本接不上。
- 为什么 TEC 接入要看实测夹套：夹套还在 100 多度时把 TEC 接上，等于让 TEC 模块贴着超出它耐温的热源，会损坏器件。

「TEC 加热」启用（原来那套）：目标 Tset > 阈值 切入电加热（按目标判，不按实测）；切回 TEC 要目标 ≤ 阈值且 Tj ≤ 阈值 − 滞回。

### 2.4 切换动作序列（每次切换都走全套）

```
① 关本工位控温输出（TCENABLE=0）
② 写 IO8R 继电器，先断后通：切电加热 = 断 TEC 功率 DO → 合切换 DO；回 TEC = 断切换 DO → 合 TEC 功率 DO
③ 若配置了切换反馈：读 DI_n 核实，超时 2 s 没对上 → 报警、保持输出关闭、不进 ④
④ 重开控温输出（TCENABLE=1）
```

带载切继电器等于让触点拉弧，先关输出再切是硬要求。全程写事件日志：
什么时候切、从哪切到哪、反馈核没核实上。

### 2.5 切换反馈（DI）——建议接，软件两种都支持

结论先说：**建议把电加热接触器的辅助触点（常开）接到 IO8R 的 DI 上**，
一个工位一根线。理由：电加热是这台机器上最危险的执行器——
继电器触点粘连、接触器没吸合、线松了，这些故障不接反馈软件根本看不见，
只能「相信自己发过的命令」。接了反馈，切换后 DI 状态对不上就立刻报警并保持
输出关闭，「命令发了但没切过去」这种事瞒不住。

软件按配置项「切换反馈」二选一：

- **有反馈**（推荐）：按 §2.4 第 ③ 步核实，界面上显示「已切至电加热（已核实）」。
- **无反馈**：跳过 ③，界面如实显示「已发切换命令（无反馈回路，未核实）」——
  不假装核实过。

### 2.6 降级运行（哪个模块掉了怎么办）

| 缺谁 | 行为 |
|---|---|
| RD105 打不开 | 设备打不开。它是控温核心，没有它这台机器什么都做不了 |
| 宇电 J7 打不开 | 设备打不开。Tr 是工艺判据和安全限值的根，宁可不开也不盲跑 |
| 宇电 J4 打不开 | 照常开，pH 一路不发数、界面显示未接。配置项「pH 模块」可直接标成没装 |
| IO8R 打不开 | 照常开，但**电加热不可用**：目标 > 阈值的下发直接拒绝，弹的话写明原因 |
| 运行中断线 | 该模块的标签发 Bad / 停发；IO8R 断线由它自己的总线错误复位兜底（§6 部署清单） |

## 3. RD105 侧（改造现有驱动）

现有 `Tec.Drivers.Rd105` 是「一台温控器 = 一个通道，TC1 测 Tr、TC2 测 Tj」。
真机拓扑不是这样，按下面改：

- **一台 RD105 = 两个通道**：TC1 → 工位 A，TC2 → 工位 B。
- **每路 TC 测的都是夹套 Tj**，控温回路闭在夹套上。TG/SPEED/TCENABLE、
  超温保护、限流全部按 TC 路号分别下发（协议本来就是 `TC1:`/`TC2:` 前缀，全支持）。
- Tr 不再来自 RD105——来自宇电 J7。RD105 会话里原来「TC1=Tr」的那套语义全部清掉。
- 到达判据（WaitReached）仍然按 **釜内 Tr** 判——工艺关心釜里到没到；
  Tr 来自另一条串口，由组合会话喂给控温能力。
- 轮询快照里 Temp1C/Temp2C 就是两工位的 Tj；duty 按 TC 路各查各的；
  告警字里 Ch1/Ch2 传感器越限分别只打相应工位的 Tj 质量位。

## 4. 宇电两台（新驱动，只读采集）

两台除输入规格外寄存器完全一致，做一套 Modbus 访问层，两个薄壳。
关键设计点（全部来自速查手册，坑也是）：

- **寄存器按参数分块不按通道分块**：读 4 路 PV 是 `03H 0600H ×4`，一帧搞定。
  轮询就这一条读 PV + 一条读报警状态（1664~），1 s 一拍足够。
- **标度自己算**：dPt 只影响面板显示，上位机读到的永远是整数。
  初始化时读 InP（2048~）拿输入规格：J7 按规格查表定小数位
  （如 Pt100 InP=21 → ×0.1，InP=22 → ×0.01）；J4 读 ScL/ScH（2052~/2056~）
  按线性定标换算 pH。**标度从设备上读出来，不在配置里再抄一遍。**
- **初始化自检**（每次开口子都做）：
  1. 读 2131 型号特征字——确认这条口子接的是温度表还是 pH 表，接反了直接报错；
  2. 读 2130 Loc——锁着就警告（锁着时写入不报错但不生效，这是最难查的坑）;
  3. 读 InP 核对输入规格与配置的探头类型一致。
- **报警状态高低字节是「奇数通道在高、偶数在低」**，传感器断线/超量程位
  （oral）映射到对应工位 Tr/pH 的 Quality.Bad——读不到不能当正常。
- 这两台**只做采集**，不用它们的控制输出、不写 At/SP。没用到的输入通道
  部署时 In 设 0（手册要求，不关会污染同号输出通道的错误标志）。
- 出厂默认地址都是 1、波特率 19.2K、8N1 无校验——各占一条串口所以地址
  不必改，但地址、波特率仍做成连接参数，默认按出厂值填。

## 5. IO8R（新驱动，DO 切换 + DI 反馈）

- Modbus RTU，8N1 固定；波特率、站号由模块上的拨码定，连接参数照着填
  （出厂默认 9600 / 站号 1）。
- 用到的点：**DO0 = 工位 A 热源切换，DO1 = 工位 B 热源切换**（断开 = TEC，
  闭合 = 电加热——断电和总线复位时继电器落回断开位，落回的必须是安全侧）；
  **DO6 = 工位 A TEC 功率线，DO7 = 工位 B TEC 功率线**（闭合 = TEC 有电；电气确认，2026-09-21；
  不控温就断着，只在打开温控要降温时合）；
  **DI0/DI1 = 对应工位电加热接触器辅助触点**（若接了反馈）。点位做成配置项。
- 每拍读回的 DO 状态里 TEC 功率线单独发一路状态量 `tecpwr`（0 断 / 1 通）进记录，
  事后「那一炉为什么降不下去」看它。
- 功能码：0x05 写单点（FF00 闭合 / 0000 断开），0x01 读回 DO 状态，0x02 读 DI。
- 轮询 1 s 一拍读 DO+DI 各一帧——DO 读回来跟自己发的命令核对，
  对不上（比如有人按了模块上的按键）也要报出来。

## 6. 安全

- **超温保护以 RD105 设备侧的保护寄存器为准**（现有「超温上限/超温下限」配置，
  开机第一件事写进设备，断了通信照样生效）。**电加热模式的最高温度就是它**：
  没有独立的硬件超温保护器，这一层是全系统最后的硬防线。
- **任何目标温度的下发都不得超过超温上限**——手动面板、配方翻译、E 级紧急
  程序一视同仁，超了就拒绝并写明「超过设备超温保护 xx ℃」。
  手动控制界面的安全设置里要能看到这个上限值（它从设备配置来，不另存一份）。
- 安全监控照旧按标签求值：Tr/Tj/dT/pH 都能设限值；宇电侧的传感器断线
  发 Bad 触发安全动作，跟现在 RD105 的告警字一个待遇。
- 「TEC 加热」不启用时回路的执行器形态（0331 / 0336）：双向挡是**加热棒 + TEC 双向**——一个 PID，正半轴加热棒、负半轴 TEC
  （乘加热比），参数按加热棒那张表，只加热 ⇄ 它互换只改限幅不复位；夹套高过 TEC 接入上限时按**只加热**（下限 0）；
  TEC 自整定按**只制冷**（占空比 ≤0，正半轴那一极接的是加热棒 SSR）。前馈按执行器各一份；外环参数按釜（离设定值最近的
  外环工作点那张表）取，不随热源切换跳。
- 双向挡（冷水机已开，0336）：放热、吸热随时接得上——釜内冲过目标功率转负够 3 s 就合 TEC；放热结束功率转正再回加热棒。
  冷水机已关的升温挡里**绝不接 TEC**（0333）：釜内冲过目标就是加热棒收到 0 自然凉，放热失控只能关加热棒 + 报警。
- 釜内（串级）控温中釜内 Tr 断了（探头会话 10 s 没新数 / 发 Bad）：回路**先保持再停控**（0329）——外环冻结、
  夹套设定钳到釜内设定、内环照跑，「Tr 丢失宽限」（缺省 30 s）内 Tr 回来无扰接续，回不来才停控、继电器全断。
  保持期不换热源。手动面板控温时安全层的 AbortChannel 是空操作，停机靠回路自身；跑配方时安全层在 ≈18 s
  （管线 15 s 转 Stale + 3 s 去抖）先中止整条通道。
- SafeStop：本工位 TCENABLE 关 + IO8R 本工位切换 DO 与 TEC 功率 DO 全部断开（停控即全断，
  跟断电落回的位置一样；E 级程序再下发降温目标时功率线重新合上）+ 采集不停——降温曲线照记。
- **风险项（如实记录）**：本机没有脱离软件的独立硬件超温保护器。
  断电/断线时的兜底是 RD105 固件里的超温保护 + IO8R 总线错误复位 +
  继电器断电落回 TEC 侧，这三层都到位才算部署完成。

## 7. 部署清单（装机必做，写给现场的人）

1. **IO8R 总线错误模式改成「复位」**（厂家配置工具改，出厂默认是「保持」——
   保持意味着断线时电加热继电器停在原位、一直加热，绝不能用默认值）。
   复位阈值默认 200×10ms=2s，够用。**按过模块上的 Reset 键会恢复出厂，改完要复查。**
2. 宇电两台各自确认 Addr/波特率与连接参数一致；Loc 确认为 0；
   没用到的输入通道 In 设 0。
3. J7 接 PT100 的话**先接好线再上电**（手册两处强调）。
4. 宇电供电必须与接触器/继电器回路完全隔离独立配电（手册注意事项第 9 条），
   读数跳变、Modbus 偶发超时先查这里。
5. 电加热接触器辅助触点接到 IO8R DI（推荐，见 §2.5），接没接如实填
   「切换反馈」配置项。
6. NPN 驱动继电器线圈要并快速恢复二极管（宇电手册要求，防反压）。

## 8. 实施顺序（每步一个补丁，能单独验证）

1. **IO8R 驱动**：Modbus RTU 帧层 + DO/DI 读写，假串口回归测试。
2. **宇电驱动**：Modbus 访问层 + J7/J4 两壳（初始化自检、标度、报警→质量位），
   假串口测试覆盖「Loc 锁着」「型号接反」「传感器断线」。
3. **RD105 双通道改造**：TC1/TC2 → 工位 A/B，语义按 §3。
4. **组合会话**：四条链路拼成一台两通道设备，热源切换状态机（§2），
   降级运行（§2.6），SafeStop 全套；HMI/台面接真标签。
5. **联调**：假串口全链路 + 界面截图验证；真机联调等硬件到位。
