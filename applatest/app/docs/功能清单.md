# TecStudio 功能清单

做完一项就把 `[ ]` 改成 `[x]`，并在行尾补一句「谁做的 / 哪个 patch」。
这份清单是我们唯一的进度表——界面对不对照原型看 `tecstudio.html`，
功能做没做看这里。

图例：`[x]` 已完成并验证过 · `[ ]` 未做或只有壳子 · **粗体** 是当前建议优先做的。

一条铁规矩：**界面上出现的每一个数都得有出处。**没有出处就显示空状态，
把「还没有」写清楚，绝不摆演示数据糊过去。

## A. 外壳 / 全局

- [x] 七视图导航（开始 / 台面 / 配方 / 配方库 / 化合物数据库 / 运行 / 数据导出）
- [x] 30px 紫渐变标题栏、52px 菜单栏，按原型 1:1
- [x] 运行控制三钮（菜单栏右边的黑色药丸），一律对**全部已启用通道**生效：
      运行（启动没跑的、继续暂停的）/ 停止（急停）/ 暂停。单路的启停在运行页的磁贴上。
      · 原型那句「模拟模式」去掉了——接上真机之后它就不对了，
        而这几个钮不论仿真真机都是同一件事，图标自己说得清
      · **原型第四颗「单步」去掉了**：跳过当前步是看着这一路当前那一步临时决定的，
        四路情况各不相同，一次全跳掉几乎不可能是人想要的结果，
        而且跳掉的每一步都写进记录撤不回来。那一颗留在磁贴上就够了
      · **停止改成红底**：四颗一个样的话，慌起来很容易把急停按成暂停
      · **三颗按状态置灰**（台面空着 / 没有一路编排了步骤 / 都在跑了 / 都停着），
        灰着的时候鼠标停上去说清为什么。从前它们恒是亮的，按下去没反应。
        「有的在跑、有的没编排」两类分开数——只要有一路编排过就笼统地说
        「都在跑了」，会跟顶栏那句「2 / 4 通道运行中」当场打架
      · **按完立刻重算，不等下一跳**：按「运行」之后通道在同一个调用栈里就变成
        运行中，可急停那颗要等最多 700ms 才亮——两颗只隔 9px，「按错了马上补一下停止」
        正好落在这个窗口里，而禁用按钮连指针事件都不路由，戳下去毫无反应
      · **底色钉死**：Fluent 的缺省悬停 / 按下 / 禁用样式都会去改按钮底色，
        鼠标压上去急停就从红变灰，看着像它自己失效了
- [x] **暂停中的通道不看配方步数**：它跑的是按下启动那一刻冻下来的快照，
      泳道后来被清空（配方页按一下「新建」就会）不影响它继续跑完。
      判据先卡步数的写法会把这条通道锁死——运行灰（0 步）、暂停也灰（它不是运行中），
      从菜单栏救不回来，而命令本身是认的（先判「能不能继续」就继续了，压根不看配方）
- [x] **「能不能启动」只有一份判据**（`ChannelRunner.CanStart` / `CanResume`）：
      菜单栏那颗、磁贴上那颗、以及 `Start()` 自己的拦截全走它。
      各写一套的话迟早「按钮亮着，按下去抛异常」——尤其 `Aborting` 这种过渡态：
      按了急停但驱动还没收完尾，只排除 Running 的写法会在那几秒里放行，
      同一路上跑起两条执行循环、两个 cts、两份记录
- [x] 窗口自绘圆角（最大化时也保留）、OffScreenMargin 补边
- [x] 主题色 ThemeFill / ThemeGap 集中在 App.axaml
- [x] 清空全部演示数据：最近实验、归档实验记录、预置通道配方、写死的实验名与导出路径
- [x] **台面与配方的存盘 / 读取**：三种文件（`.tec` 实验 / `.tecbench` 台面 / `.tecrecipe` 配方），
      JSON、可读、可 diff；原子写入（先临时文件再替换）；格式版本超前直接拒绝；
      读盘出错给人话不给堆栈。11 条回归测试。
- [x] **配方库与化合物库改成全局，存进 SQLite**（数据目录下 `tecstudio.db`）：
      这两样跟**这台机器**走，不跟某一份实验走——工艺模板和物性数据在哪份实验里都是那一套。
      · 实验文件（`.tec`）里不再带配方库；从前每份实验都带一份副本，同一条配方在几份实验里
        各存一遍，改了一处别处还是老的，分不清哪份算数
      · 打开老格式实验时，里头带的配方库**并进全局库**（按配方号认，库里已有的不动），
        并了几条在状态行上说一句——不悄悄扔掉操作人在别的机器上编的工艺
      · 老的 `library.json` 开机自动搬进数据库，原文件改名 `.bak` 留着
      · 为什么不接着用 JSON：写到一半断电整份废掉、每改一条都要整份重写、
        两个窗口同时开着是后写的覆盖先写的。SQLite 这三样都有解
      · 库开不起来（盘满 / 只读 / 被占用）不影响程序启动，只是这一开机存不住库
      · 14 条回归：存读一个字段不少、界面上删掉的库里也真没了、顺序保住、两个库互不干扰
- [x] 自绘确认框 ConfirmDialog（紫色标题栏 + 圆角，与主窗口一套；Enter 主按钮 / Esc 取消）
- [ ] 全局撤销 / 重做
- [x] 标题栏显示当前实验名，改过没存加星号；左上角两个图标接了运行 / 保存
- [ ] 标题栏「关于」入口
- [ ] 标题栏「设置」入口（时标、单位、数据目录、操作人）
- [ ] 标题栏「帮助」入口
- [ ] 用户与权限（右上角「管理员」目前是死的）

## D. 配方视图

- [x] 指令库分 6 组，图标与文案照原型
- [x] **按实际硬件精简到 20 条**（通用 8 · 温度 4 · 搅拌 1 · 加料 1 · pH 2 · 在线分析 4）：
      一条指令 = 设备真正会做的一个动作，同一动作的不同用法是参数不是新指令。
      升温至 / 降温至 / 夹套控温 / 釜内控温 → 一条「控温」（方向看目标温度，对象是参数）；
      设定转速 / 转速梯度 / 停止搅拌 → 一条「搅拌」（转速 0 即停机，梯度就是到达用时写长）；
      恒速加料 / 定量加料 / 分段加料 → 一条「加料」（时长 = 体积 ÷ 流量，分段用循环）；
      pH 保持与 pH 反馈加料本是同一个闭环，并成一条归 pH 模块。
      删掉结晶模式（没有回流冷凝硬件）、pH 上下限报警（安全联锁已覆盖）、
      Tr−Tj 记录（Tr/Tj 本来一直在记）
- [x] 老配方自动翻译（`RecipeMigration`）：旧指令 Id 就地翻成新的，换算得出来的照算，
      换算不出来的原样留着让校验器报——猜一个默认值填进去等于替操作人改工艺参数
- [x] 多通道泳道，每通道一条配方
- [x] 步骤卡（模块色图标 + 整句描述 + 预计开始 / 耗时）
- [x] 参数表单由驱动 schema 渲染，含多分段表
- [x] **温度分段配曲线预览**：表格上方画出这条配方真正会走的形状（斜线变温、平线保持，
      横轴长度就是耗时），改表格曲线立刻跟着变。画不画、画成哪种图由指令自己声明
      （`TableSpec.Chart`），界面不按标题猜。起笔温度取排期算出来的「这一步开始时的温度」
- [x] 一键复制到其它通道
- [x] 应用配方库 / 存入配方库
- [x] 泳道换挂通道、删除泳道
- [x] 泳道跟着通道走：拖进一台反应器多两条空泳道，台面空着就是空状态
- [x] 排期与时长估算（含循环、串行推进）
- [x] 工具条「新建」（把当前通道清成空配方，名字保留）
- [x] **工具条「撤销」/「重做」**：按通道分开的快照栈，深 30。
      在 CH2 上撤销不会把 CH1 的改动一起回滚——四条泳道摆在一屏上，
      撤错了通道比没有撤销更吓人。改参数按「一次选中并编辑」合成一笔，
      连按几下上下箭头不会变成十次撤销
- [x] 步骤属性面板对齐原型：标题恒为「步骤属性」，未选中给一句提示；
      选中时 prop-head（模块色块 + 指令名 + 所属通道）；无参数的指令明说
      「该指令无需设置参数」
- [x] 执行选项两个开关都真的影响运行：「失败时暂停并报警」由执行引擎读，
      「跳过该步骤」走 Step.Enabled（排期与执行都认）
- [x] 「应用配方库」下拉带步数；「管理配方库 →」跳到配方库页
- [x] 通道状态表按台面上**全部**孔位列（已停用 / 未建标签 / N 步 / 空配方），
      名称在前、通道标签灰字、状态右对齐
- [x] **所有折叠小节都真的能折叠**：原来面板里那些「圆圈箭头 + 小标题」多数只是画上去的，
      点了没反应、箭头也不动。配方右栏 3 处、导出 8 处、配方库 1 处、化合物 1 处全部接上，
      左侧步骤库的分组箭头也改成跟着开合转
- [x] 观感统一，全部跟着台面走：属性面板 = 白底 + #ece9f5 浅紫内容块；
      左侧库 = 一个模块一块 #ece9f5，块之间 3px 白缝（配方的步骤库与台面的设备库同款）
- [x] **拖拽**：从左侧步骤库拖进任意泳道的任意位置；泳道内拖动换序；
      跨泳道把步骤整条挪到别的通道。落点指示画在卡片之间那截连接线上
      （高度不变，拖动时版面不跳），落点泳道整条描蓝，被拖走的卡自己变淡。
      拖到空处松手等于没拖，Esc 撤销。点一下加到当前通道的老办法照旧能用
- [x] **循环嵌套看得见**：循环体按层缩进，让出的位置画竖线；循环开始 / 结束行
      自己算外层，两条对得齐。泳道整体仍是 270 宽，四条泳道横向对齐不受影响
- [x] **配方校验结果上界面**：有问题才出现一条校验条，写「N 个错误 · M 个提醒」
      并逐条列出；点一条跳到出问题的那一步。「预计总时长」是 Info，不混进问题清单
- [x] **配方文件单独导入 / 导出**（`.tecrecipe`）：工具条右侧两个按钮。
      导入是整份替换当前通道（不是合并——合并出来的步骤顺序没人说得清），
      替换前记一笔，撤销拉得回来；老指令 Id 顺带翻译并在提示里说明

- [x] 「导入」——.tecrecipe 收进库，与配方页那个导入同一套读盘与老指令翻译
- [x] 右栏观感跟台面属性走：白底面板 + #ece9f5 内容块
- [x] 配方库持久化：存在全局库 `tecstudio.db`，另存 / 删除即时落盘。
      **不再跟着实验文件走**（见 §A 那条）
- [x] **存进去立刻看得见**：配方库改成可观察集合，配方页与配方库页各自跟着变。

- [x] **库里的「最近更新」是真的更新时刻**：存进来的那一刻重打时间戳，
      不再沿用原件的时间（沿用会显示成一直没动过）
- [x] 台面上没有通道时，「应用配方库」和「存入配方库」明说没得可用，
      不再凭空造出一条不存在的泳道
- [x] 配方页每个动作都回一句话（存了几步、应用到哪条通道、导入替换了什么），
      不再是点完什么反应都没有

      紧跟一条「继续」，读的人会以为有人又把它开起来了。
      暂停着按「跳过」倒是真的回到了运行，那一条照记

- [x] 结束原因按指令语义逐条给措辞
- [x] **停止之后把设备收到安全态**（`IDeviceSession.SafeStopAsync`）：
      中止本身只取消配方的执行循环，机器不会因此停下来——温控器还守着最后那个
      设定值。实测过：按下停止时 37.2 ℃，十几秒后一路升到 60 ℃ 稳住，
      操作人按那颗红钮时想的绝不是这个。
      · **该关什么归驱动说**，Core 不认识具体设备。反应器：切加热、**保搅拌**
        （热液不搅有局部过热 / 结块 / 暴沸的风险，停搅拌比继续搅危险；
        要停就在配方末尾自己写一条转速 0，那是工艺决定不是停机动作）。
        加料泵：停泵并报出本趟累计加了多少（加料不可逆，配比要对得上账）。
        探头：什么都不停，照读不误——停下来那段的 pH / 浊度正是最该留的
      · **做了什么逐条进记录**（`EventKind.SafeStop`，抽屉里徽标写「停机」）：
        驱动没实现就照实说「输出保持原样」，不假装停干净了；停不下来记「停机失败」，
        那是最该留痕的一种——机器还开着而且没人知道
      · 停机用的**不是**那个刚被 Cancel 的令牌（拿它去停设备等于一条指令都发不出去），
        另开一个 10 秒预算的，某台不响应也不拖住别的几台
      · **只在非正常结束时做**。正常跑完不动它：收尾状态是配方作者定的
        （降温结晶跑完就该保持在 5 ℃ 过夜，替他关掉是帮倒忙）

- [x] **`ChannelRunState` 补上终态 `Aborted`**：`Aborting` 是「正在收尾」的过渡态，
      从前收尾完了记录上留的还是它，界面读出来是「正在停止」，
      一个早已停下的通道永远显示成正在停
- [x] **顶栏数的是现在真在跑的那几路**：从前数的是「启动过的」，

- [x] **台面改动会把正在跑的通道停下来并记一笔**：台面一动就重开全部设备会话、
      重建全部 Channel 对象。老执行器攥着已经 Dispose 的会话，让它接着跑
      等于对着空气下指令——界面上「运行中」，釜温一动不动，而且一声不吭。
      现在：重建前先中止并写进记录，重建后按新的 Channel 对象换执行器，
      台面上已经没有的通道把执行器摘掉
- [x] **手动标记事件**：执行记录抽屉里一个输入框 + 「记一笔」。落成该通道记录链上的
      一条 OperatorMark 事件，署当前操作人，带上当时正在跑的那一步——
      导出时答得出「这一笔是哪一步里出的事」。没启动的通道不给标（没有链可挂），
      空标记不进记录。7 条回归
- [x] **三块 pane 真的能收起来**：原型里那个圆圈箭头只有 cursor:pointer，点了不动。
      收起后只剩 28px 竖标签，腾出的宽度给还开着的那块
- [x] 空状态：台面上没有通道时三块 pane 各说各的，不画一堆空格子；
      趋势图分「还没启动」和「启动了还没采到点」两种说法——该做的下一步不一样
- [x] 磁贴对齐原型：停用的只写「已停用 + 机A · A 孔」（数据行全是「—」看着像坏了），
      没启动的挂一个灰点。孔位说法与台面视图共用一处，两页不会各叫各的
- [x] 顶栏的实验名跟着打开的实验变（早先它不在周期刷新里，一直写着「未命名实验」）
- [x] 图表贴边的刻度不再被裁成半截（右下角那种「17:1」）
- [x] **运行中改参数**（FR-5.5 / §7.6，入口在「步骤进度」工具条上的「改参数」，
      对选中的那一路开一块 326px 面板）：
      · **每一步都写清「改了什么时候生效」**——同一个改动落在当前步、后面某一步、
        循环体里已跑过的一步上，结果完全不同；最坏的一种是**什么都不会发生**
        （这一步跑完了、配方里又没有循环），那时人会以为改成了，一直等一个不会来的效果。
        所以那一条直接拦下来并说明理由，不让他白改
      · 指令自己声明支不支持热改（`SupportsHotEdit`）。不支持的当前步照实说
        「要改先暂停这一路，或者改后面的步骤」；分段表（梯度控温）不进热改——
        改一行会把后面几段的时间全推掉，本趟排期就对不上了
      · **基线 / 现行 / 改为三行摆在一起**：基线是启动那一刻冻下来的，永不变，
        偏差照常按它算；改过之后「现行」才出现。改一个格子「改为」这一行立刻跟着变
      · **修改原因必填**。一条没有理由的运行中改参数，事后没有任何人能解释它
      · 编辑的是副本，取消不留痕；应用才交给 `ProposeEdit` 走校验（超设备限值当场退回）
      · 跑完了不给改：那趟记录已经收口，照改会往一条结束了的链上再追一条「参数修改」
      · **面板每 700 ms 刷一次，但内容没变就一个字都不动**——实测抓到的：
        无脑重建会把操作人正在输入的那个数当场抹掉（把 300 改成 60，松手又变回 300）
      · 6 条回归
- [x] **报警确认与处理**（§7.5）：
      · **停加料 / 停加热从前落在 `default` 分支上什么也没做**。限值上写着
        「超限停加料」，超限了泵却照打——比没有这条限值更糟：现场以为有人兜着。
        现在照能力接口真的去做（上层只问「这一路能不能停加热」，不认设备型号），
        做了什么逐条进记录；这一路没有那种设备就照实说，不假装停过
      · **一次越限只报一次**。温度贴着上限抖，一秒一条能在十分钟里刷出六百行，
        真正要人管的那条反而被埋掉。传感器失效（无信号 / Bad / Stale / 超时未更新）
        与越限走同一条去抖路径——读不到值绝不当作正常
      · **恢复也是一条事实**，带上响了多久。报警响了三秒还是三小时，读记录的人要分得出
      · **触发和确认是两件事**：机器判断条件成立就触发，有没有人看见、怎么处理只有人能落。
        所以报警不会自己消失——条件恢复了也要人确认过才翻篇（「已恢复，待确认」这一档
        不能省：一条自己好了的报警要是悄悄消失，操作人根本不会知道刚才出过事）。
        确认可带一句处理说明，署名进记录
      · 确认**不等于**解除：条件还成立的仍然留在清单上，只是从此答得出谁看过
      · 顶上一条报警带，一条都没有就整条不画。**刻意不做成弹框**——
        模态窗会把急停那颗钮挡在后面，而报警恰恰是最需要人能马上按停的时候
      · **缺省限值比设备工作范围松一档**（±1 ℃ / +25%）。实测撞出来的：
        设备允许 16 ℃/min，配方照 16 ℃/min 跑，噪声让实测斜率在 16 上下抖——
        限值卡死在 16，一次完全正常的升温就被判成超速并中止整批。
        联锁防的是「跑飞了」，不是「贴着上限干活」
      · 越限那个数印得出和限值的差别（「高于上限 180.0（实测 180.01）」，
        而不是「180.0（180.0）」那种看着像程序算错了的写法）；
        消息不自带通道前缀（清单和记录都有「通道」这一列，否则读成「CH1 CH1 Tr 高于上限」）
      · 台面重建时正在报的一并收尾（限值马上就没了，留着只会等一个再也不会来的恢复），
        没确认过的仍留在清单上等人确认
      · 17 条回归
- [x] **趋势图导出图片**（趋势工具条上的「导出图片」）：不是截屏——
      另排一份离屏的可视树，2× 渲染，把实验名 / 通道与孔位 / 窗口 / 时间范围 /
      采样点数 / 导出时刻与操作人一起写进去。**仿真跑出来的单独一块红底标出来**，
      绝不能和真实数据混进一份报告（§8.1）。图用的就是界面上那个控件，
      一笔一画完全一致——另写一份导出专用的画法迟早和屏幕上看到的对不上。
      空图不给导：一张什么都没有的 PNG 贴进报告里比没有更糟
- [x] **记录链上的追加是线程安全的**：往一条通道记录上追加的不止一个线程——
      执行循环在线程池上跑，安全层在自己的定时器线程上求值，手动标记与报警确认
      来自界面线程；而读的几乎总是界面线程（每 700 ms 重排一次记录表）。
      裸 List 迟早在枚举中途被 Add 撞上，那是一个当场抛异常、复现全靠运气的崩溃。
      现在读回快照（一趟几百条，复制远比把锁摊给调用方划算）

      那种表交出去等于没交。时刻是日期格式、时长是 `[h]:mm:ss`，能直接算
- [x] **报告模板引擎**（`ReportDoc` + `ReportBuilder` + `ReportLayout`）：
      **一份内容、两种去处**——Word 与 PDF 读同一份 `ReportDoc`，措辞只写一遍，
      两种格式里就不会有第三种说法。报告里出现的每个数都能在随附的
      steps.csv / data.csv 里找到出处，没有一句是模板凑的
- [x] **三种模板**：完整实验报告（封面 · 概要 · 趋势曲线 · 步骤执行记录 · 事件与报警 ·
      配方与台面）· 实验摘要（一到两页，只留概要、曲线和超差的步骤）·
      GLP 归档报告（完整报告 + 审计追踪全文 + 校验码表 + 签名块）
- [x] **Word 排版**（`DocxWriter`）：标题 / 表格 / 图片 / 页脚页码都是 Word 的原生对象，
      分页交给 Word 自己——硬按绝对坐标摆，人一改字号整份文档就散了。
      表头行标了「跨页重复」，与 PDF 一致
- [x] **PDF 排版**（`ReportLayout` + `PdfWriter`）：自己分页、自己排版、
      **内嵌中文字体子集**（`TrueTypeFont` 解析 + 子集化 + Identity-H CID 字体 + ToUnicode）。
      写的是真文字：能选、能复制、能全文搜索——把每页渲染成图片塞进 PDF 也能出中文，
      但那样的报告搜不到「CH2」，交给审计的文件不该是一叠截图。
      整份中文字体十几兆，子集之后是几百 KB
- [x] **字体里没有的字换写法、换不掉就丢掉**：「25 ℃」宁可印成「25 °C」，
      也不能留一个 .notdef 方框在交出去的报告上。这台机器上第一个候选字体
      （Droid Sans Fallback）是纯 CJK 的，一个数字都没有——选字体时中文和西文都得查，
      只查汉字的话，「25.4 ℃」「CH1」「2026-08-17」会全是空白而标题看着好好的
- [x] **预览报告**：排的是**导出时那一份排版**——同一个 `ReportBuilder`、同一个
      `ReportLayout`，界面上按同一批图元画（`ReportPageView`）。预览里看到第几页在
      哪儿断，PDF 就在哪儿断；界面另排一套的话，「预览」这两个字就是假的。
      可缩放、可适合宽度；校验码那一节照实说「导出时才算得出」
- [x] **表格跨页把表头重画一遍**；数字列一律不折行（「09:00:00」折成两行是
      「09:00:0」和「0」，看着像两个数）；文字列最多折两行再掐
- [x] **本次导出写入系统日志**（`SystemLog`，只追加、一月一份、制表分隔，
      用记事本就能打开）：谁、什么时候、把哪几条用什么格式导到哪儿去了、写了几个文件。
      它和 run.glp 分工不同——后者记「这一炉里发生了什么」，日志记「这台机器上有人做了什么」；
      实验记录里说不出「谁把它拷走了」。开关机与批次起止也各记一笔。
      GLP 那一节底下有「查看系统日志」，用系统默认程序打开当月那份
- [x] **读取跨次开机的历史归档实验**（`RunArchive`）：一炉一个目录，
      run.json（执行记录）+ tags.json（标签说明）+ samples.tsv.gz（采样）。
      切到导出页与关程序时各归档一次；内容没变的不重写（一炉跑完之后每次切页
      都重压一遍几兆采样，除了磨硬盘没有别的用）。**记录编号不与归档撞号**——
      同一天关掉再开，第一炉又会拿到 -001，而编号就是归档目录名，撞上就是
      上午那一炉被下午这一炉盖掉。读不动的那一份跳过并在页脚说「有 N 份读不回来」，
      不悄悄吞掉
- [x] **归档的采样走同一套导出器**（`ISampleSource`）：导出器只问「给我这一路的点」，
      不必知道点是从内存还是从盘上来的。归档时采样已被环形缓冲顶掉过一截的，
      记一个标记，导出页、报告封面与 Excel 概要页都照实说「只有后半段」
