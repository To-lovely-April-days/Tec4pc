# TecStudio 功能清单

做完一项就把 `[ ]` 改成 `[x]`，并在行尾补一句「谁做的 / 哪个 patch」。
这份清单是我们唯一的进度表——界面对不对照原型看 `tecstudio.html`，
功能做没做看这里。

图例：`[x]` 已完成并验证过 · `[ ]` 未做或只有壳子 · **粗体** 是当前建议优先做的。

一条铁规矩：**界面上出现的每一个数都得有出处。**没有出处就显示空状态，
把「还没有」写清楚，绝不摆演示数据糊过去。

## A. 外壳 / 全局

- [x] 七视图导航（开始 / 台面 / 配方 / 配方库 / 化合物数据库 / 运行 / 数据导出）
- [x] **第八项「配料表」**——原型里没有这一页，插在化合物数据库后面：
      它消费化合物库里的物性，产出加料步骤的体积，位置就在这两者之间（见 F2 节）
- [x] 30px 紫渐变标题栏、52px 菜单栏，按原型 1:1
- [x] 运行控制三钮（菜单栏右边的黑色药丸），一律对**全部已启用通道**生效：
      运行（启动没跑的、继续暂停的）/ 停止（急停）/ 暂停。单路的启停在运行页的磁贴上。
      · 原型那句「模拟模式」去掉了——接上真机之后它就不对了，
        而这几个钮不论仿真真机都是同一件事，图标自己说得清
      · **原型第四颗「单步」去掉了**：跳过当前步是看着这一路当前那一步临时决定的，
        四路情况各不相同，一次全跳掉几乎不可能是人想要的结果，
        而且跳掉的每一步都写进记录撤不回来。那一颗留在磁贴上就够了
      · **停止改成红底**：四颗一个样的话，慌起来很容易把急停按成暂停
      · **三颗按状态置灰**（台面空着 / 没有一路编排了步骤 / 都在跑了 / 都停着），
        灰着的时候鼠标停上去说清为什么。从前它们恒是亮的，按下去没反应。
        「有的在跑、有的没编排」两类分开数——只要有一路编排过就笼统地说
        「都在跑了」，会跟顶栏那句「2 / 4 通道运行中」当场打架
      · **按完立刻重算，不等下一跳**：按「运行」之后通道在同一个调用栈里就变成
        运行中，可急停那颗要等最多 700ms 才亮——两颗只隔 9px，「按错了马上补一下停止」
        正好落在这个窗口里，而禁用按钮连指针事件都不路由，戳下去毫无反应
      · **底色钉死**：Fluent 的缺省悬停 / 按下 / 禁用样式都会去改按钮底色，
        鼠标压上去急停就从红变灰，看着像它自己失效了
- [x] **暂停中的通道不看配方步数**：它跑的是按下启动那一刻冻下来的快照，
      泳道后来被清空（配方页按一下「新建」就会）不影响它继续跑完。
      判据先卡步数的写法会把这条通道锁死——运行灰（0 步）、暂停也灰（它不是运行中），
      从菜单栏救不回来，而命令本身是认的（先判「能不能继续」就继续了，压根不看配方）
- [x] **「能不能启动」只有一份判据**（`ChannelRunner.CanStart` / `CanResume`）：
      菜单栏那颗、磁贴上那颗、以及 `Start()` 自己的拦截全走它。
      各写一套的话迟早「按钮亮着，按下去抛异常」——尤其 `Aborting` 这种过渡态：
      按了急停但驱动还没收完尾，只排除 Running 的写法会在那几秒里放行，
      同一路上跑起两条执行循环、两个 cts、两份记录
- [x] 窗口自绘圆角（最大化时也保留）、OffScreenMargin 补边
- [x] 主题色 ThemeFill / ThemeGap 集中在 App.axaml
- [x] 清空全部演示数据：最近实验、归档实验记录、预置通道配方、写死的实验名与导出路径
- [x] **台面与配方的存盘 / 读取**：三种文件（`.tec` 实验 / `.tecbench` 台面 / `.tecrecipe` 配方），
      JSON、可读、可 diff；原子写入（先临时文件再替换）；格式版本超前直接拒绝；
      读盘出错给人话不给堆栈。11 条回归测试。
- [x] **配方库与化合物库改成全局，存进 SQLite**（数据目录下 `tecstudio.db`）：
      这两样跟**这台机器**走，不跟某一份实验走——工艺模板和物性数据在哪份实验里都是那一套。
      · 实验文件（`.tec`）里不再带配方库；从前每份实验都带一份副本，同一条配方在几份实验里
        各存一遍，改了一处别处还是老的，分不清哪份算数
      · 打开老格式实验时，里头带的配方库**并进全局库**（按配方号认，库里已有的不动），
        并了几条在状态行上说一句——不悄悄扔掉操作人在别的机器上编的工艺
      · 老的 `library.json` 开机自动搬进数据库，原文件改名 `.bak` 留着
      · 为什么不接着用 JSON：写到一半断电整份废掉、每改一条都要整份重写、
        两个窗口同时开着是后写的覆盖先写的。SQLite 这三样都有解
      · 库开不起来（盘满 / 只读 / 被占用）不影响程序启动，只是这一开机存不住库
      · 14 条回归：存读一个字段不少、界面上删掉的库里也真没了、顺序保住、两个库互不干扰
- [x] 自绘确认框 ConfirmDialog（紫色标题栏 + 圆角，与主窗口一套；Enter 主按钮 / Esc 取消）
- [ ] 全局撤销 / 重做
- [x] 标题栏显示当前实验名，改过没存加星号；左上角两个图标接了运行 / 保存
- [ ] 标题栏「关于」入口
- [ ] 标题栏「设置」入口（时标、单位、数据目录、操作人）
- [ ] 标题栏「帮助」入口
- [ ] 用户与权限（右上角「管理员」目前是死的）

## D. 配方视图

- [x] 指令库分 6 组，图标与文案照原型
- [x] **按实际硬件精简到 20 条**（通用 8 · 温度 4 · 搅拌 1 · 加料 1 · pH 2 · 在线分析 4）：
      一条指令 = 设备真正会做的一个动作，同一动作的不同用法是参数不是新指令。
      升温至 / 降温至 / 夹套控温 / 釜内控温 → 一条「控温」（方向看目标温度，对象是参数）；
      设定转速 / 转速梯度 / 停止搅拌 → 一条「搅拌」（转速 0 即停机，梯度就是到达用时写长）；
      恒速加料 / 定量加料 / 分段加料 → 一条「加料」（时长 = 体积 ÷ 流量，分段用循环）；
      pH 保持与 pH 反馈加料本是同一个闭环，并成一条归 pH 模块。
      删掉结晶模式（没有回流冷凝硬件）、pH 上下限报警（安全联锁已覆盖）、
      Tr−Tj 记录（Tr/Tj 本来一直在记）
- [x] 老配方自动翻译（`RecipeMigration`）：旧指令 Id 就地翻成新的，换算得出来的照算，
      换算不出来的原样留着让校验器报——猜一个默认值填进去等于替操作人改工艺参数
- [x] 多通道泳道，每通道一条配方
- [x] 步骤卡（模块色图标 + 整句描述 + 预计开始 / 耗时）
- [x] 参数表单由驱动 schema 渲染，含多分段表
- [x] **温度分段配曲线预览**：表格上方画出这条配方真正会走的形状（斜线变温、平线保持，
      横轴长度就是耗时），改表格曲线立刻跟着变。画不画、画成哪种图由指令自己声明
      （`TableSpec.Chart`），界面不按标题猜。起笔温度取排期算出来的「这一步开始时的温度」
- [x] 一键复制到其它通道
- [x] 应用配方库 / 存入配方库
- [x] 泳道换挂通道、删除泳道
- [x] 泳道跟着通道走：拖进一台反应器多两条空泳道，台面空着就是空状态
- [x] 排期与时长估算（含循环、串行推进）
- [x] 工具条「新建」（把当前通道清成空配方，名字保留）
- [x] **工具条「撤销」/「重做」**：按通道分开的快照栈，深 30。
      在 CH2 上撤销不会把 CH1 的改动一起回滚——四条泳道摆在一屏上，
      撤错了通道比没有撤销更吓人。改参数按「一次选中并编辑」合成一笔，
      连按几下上下箭头不会变成十次撤销
- [x] **步骤上标工艺阶段**：执行选项那一节多一个下拉（未标注 / 升温 / 保温 / 降温 /
      结晶 / 溶解 / 蒸馏 / 加料 / 反应 / 淬灭 / 后处理）。标了就进记录、进报告
- [x] **步骤复制只有一处**（`Step.CopyWith`）：从前快照、热改各手抄一遍字段清单，
      结果热改之后「失败时暂停并报警」被抄丢、退回默认的 true——操作人明明关掉了它，
      改一次参数又自己打开了。加字段时只改这一处，就不会再抄漏
- [x] 步骤属性面板对齐原型：标题恒为「步骤属性」，未选中给一句提示；
      选中时 prop-head（模块色块 + 指令名 + 所属通道）；无参数的指令明说
      「该指令无需设置参数」
- [x] 执行选项两个开关都真的影响运行：「失败时暂停并报警」由执行引擎读，
      「跳过该步骤」走 Step.Enabled（排期与执行都认）
- [x] 「应用配方库」下拉带步数；「管理配方库 →」跳到配方库页
- [x] 通道状态表按台面上**全部**孔位列（已停用 / 未建标签 / N 步 / 空配方），
      名称在前、通道标签灰字、状态右对齐
- [x] **所有折叠小节都真的能折叠**：原来面板里那些「圆圈箭头 + 小标题」多数只是画上去的，
      点了没反应、箭头也不动。配方右栏 3 处、导出 8 处、配方库 1 处、化合物 1 处全部接上，
      左侧步骤库的分组箭头也改成跟着开合转
- [x] 观感统一，全部跟着台面走：属性面板 = 白底 + #ece9f5 浅紫内容块；
      左侧库 = 一个模块一块 #ece9f5，块之间 3px 白缝（配方的步骤库与台面的设备库同款）
- [x] **拖拽**：从左侧步骤库拖进任意泳道的任意位置；泳道内拖动换序；
      跨泳道把步骤整条挪到别的通道。落点指示画在卡片之间那截连接线上
      （高度不变，拖动时版面不跳），落点泳道整条描蓝，被拖走的卡自己变淡。
      拖到空处松手等于没拖，Esc 撤销。点一下加到当前通道的老办法照旧能用
- [x] **循环嵌套看得见**：循环体按层缩进，让出的位置画竖线；循环开始 / 结束行
      自己算外层，两条对得齐。泳道整体仍是 270 宽，四条泳道横向对齐不受影响
- [x] **配方校验结果上界面**：有问题才出现一条校验条，写「N 个错误 · M 个提醒」
      并逐条列出；点一条跳到出问题的那一步。「预计总时长」是 Info，不混进问题清单
- [x] **Error 真阻断启动**（CH-5「阻断下发」）：从前校验器只管把提示条染红，
      启动路径看都不看——「错误」和「警告」的差别只剩颜色。现在闸设在
      `ChannelRunner.Start` 里：参数超范围、指令没安装、通道缺能力、泵未标定，
      一条 Error 就拒绝下发，异常里带完整错误清单
  - 拦在执行器不拦在界面：按钮、整机启动、将来的远程接口，谁来都过同一道闸
  - 拒绝了要说人话：运行页顶栏红字念第一条错误 + 「共 N 条，其余见配方页校验条」，
    并写进系统日志（谁按的、为什么没开）；整机启动时被拦的通道也留一笔，
    其余通道照常开
  - 拦下就是没发生：通道状态不动、记录里一炉都没有，换一份好配方立刻能开
- [x] **步骤身份用稳定 StepId，不用数组下标**（CH-6.5）：事件（热改 / 手动标记 /
      资源等待 / 备注）和校验条挂步骤一律记 `StepId`——下标在插步 / 删步之后
      整体错位，审计追踪就指不准被改的对象了。点校验条跳步骤也按 Id 找。
      老归档里存的下标读盘时尽力换算回来（先对步骤记录行号，再对配方下标），
      对不上的照实放空——审计里指错对象比空着更糟
- [x] **配方文件单独导入 / 导出**（`.tecrecipe`）：工具条右侧两个按钮。
      导入是整份替换当前通道（不是合并——合并出来的步骤顺序没人说得清），
      替换前记一笔，撤销拉得回来；老指令 Id 顺带翻译并在提示里说明

## F2. 配料表与化学计量

**原型里没有这一页。**它是照着「化学表里的计算引擎直接连着化合物库，按给定的化学计量
因子算出所需用量，算出来的量再直接联到实验的加料表」这条链补的——库里的分子量和密度
从此是被加料任务实际消费的，不是摆设。

- [x] **一路一张表**，跟着实验走（存进 .tec，不是全局的）：四个通道跑四组不同的量，
      而苯甲酸的分子量在哪一路都是 122.12
- [x] **基准是「限制试剂定量，其余按当量算」**。限制试剂那一行给一个实打实的量
      （称多少克 / 量多少毫升 / 要多少毫摩尔），它定下这一炉的物质的量；
      别的行按当量、或者按倍量（每 1 g 限制试剂用几 mL，溶剂的常规写法）跟着它走
- [x] **纯度校正**。65 % 的硝酸要拿到 10 mmol 的 HNO₃，得称 10 mmol 对应的质量再除以
      0.65。不校正的话每一步都少投三分之一——这是整个引擎存在的理由
- [x] **密度换体积**。泵下发的是体积，配料算出来的是质量，中间只有密度。
      **密度没填就算不出体积**，那时候照实说「缺密度」，不拿 1 g/mL 顶
- [x] **缺什么就说缺什么**。摩尔质量空着，这一行的 mmol 和应称量就都是空格子，不是 0；
      纯度没填按 100 % 计，但必须说一声（不说等于替这瓶料担保）
- [x] 物性**连库即快照**（CH-D1）：连上库那一刻把摩尔质量 / 密度 / 纯度**拷贝**进行里
      并盖章（哪一版库、什么时刻），之后库里怎么改这一行都不动——不然今天修一下库里的
      密度，去年那炉报告里的「应量取」就被追溯性改掉了。拷贝只填空格，**行上写了的赢**：
      手里这瓶 65 % 的硝酸，不能因为库里那条写着 68 % 就按 68 % 算
  - 盖了章的行是**自足**的：空字段就是「快照时库里也没有」，不回头吃活库——
    日后有人往库里补条密度，这行也不悄悄吃进去
  - **「刷新库值」**是唯一一条跟上库的路，人显式按出来：物性改回库里当前值并重新盖章，
    改了什么逐条列在状态条上（盖掉了行上手改的数也看得见）
  - 化合物库带**版本号**（每写一次 +1，SQLite meta 表），章上盖的就是它——
    复核的人能指认「按哪一版库算的」
  - 老 .tec 打开时**补章**（把现取的值落到行上、盖当天的章），补了哪几行说一声，
    并标脏——不存盘的话章只活在内存里，快照时刻自己会漂
  - 报告 / Excel 对已快照的基线**不再传活库**，从机制上杜绝历史记录跟着今天的库变；
    早于快照机制的归档照实喊出来（「物性取自导出时库的当前值」），未快照的行
    在 Excel「物性快照」列和假设列里逐个点名。表脚多一句「物性快照：化合物库第 N 版」
- [x] 不连库的行（内部代号）靠行上自己填的物性照样算得出来
- [x] **四通道对照矩阵**（CH-3.6）：工具条「对照」一键切换，把各通道互相独立的表
      按组分对齐成「组分 × 通道」矩阵。**数据模型不动**——矩阵是视图，
      格子直接写那个通道自己的行；「共享」发生在复制那一下，不在存储里，
      所以「CH1 运行中冻结、CH3 还在编辑」天然成立（运行中的列整列锁灰）
  - 对齐凭据先 CAS 后规整名（全角空格 / 大小写不碍事）；行序按各通道出现先后合并；
    同通道重复录的两行各占一行不合并——合并会把两行不同的量挤进一格
  - 三层显示切换：给定量（可改）/ 应称量（算出来的，只读）/ 实投（可回填）
  - 行内差异与缺行整行着琥珀色——四路在筛什么一眼扫得出来；缺行摆「—」，
    缺本身就是信息
  - 「复制到其余通道」：当前通道的表整张克隆铺开，**保留行 Id**（各通道配方
    是同一模板应用来的话，加料步骤引用靠这一点续上）；目标原表被顶掉说一声，
    运行中的通道跳过；写系统日志
  - 典型筛选流程：单表建好 CH1 → 复制铺开 → 矩阵里逐格改各路的量 →
    差异着色自动把「这四炉在筛什么」摆出来
- [x] 角色：限制试剂 / 试剂 / 溶剂 / 催化剂 / 淬灭 / **目标产物** / 其他。
      产物不投料，摆在表里是为了**理论产量与收率**——实际产量回填就有收率
- [x] 实投一栏：算出来的是应称量，这一格是真投进去的，差多少一眼看得见（超 2 % 标红）
- [x] **实投折算**（CH-3.5）：回填实投后按同一套纯度折算反推——实投折合多少 mmol、
      实际当量几何（以限制试剂**实投**为基准，没回填则按计划）、较计划过量 / 欠量几个点。
      质量偏差答不了「相对量」的问题：限制试剂自己也称偏了的时候，摩尔比才是真相。
      组分详情一行小字 + Excel 三列（实投 mmol / 实际当量 / 过量 %）
- [x] **收率分母按限制试剂实投**：限制试剂少称了 5 %，理论上限就低 5 %，
      拿计划量当分母会把一炉好收率说成差的。实投没回填只好按计划算，
      但假设列和表脚都把这层说出口；收率打印必带基准（「按实投折算 X mmol 计」/
      「按计划投料计」）——表脚的理论产量按计划、收率按实投，两个基准差在哪写明白，
      复核的人拿计算器一除才对得上
- [x] **摩尔浓度**（CH-C7）：限制试剂 ÷ 溶剂总体积，mol/L。任何一个溶剂行算不出
      体积（缺密度）就不给数——按打了折的体积算浓度，得出的数偏高还看着可信。
      合计区一行 + 报告表脚一句
- [x] **限制试剂的建议**（CH-3.2，建议不代填）：没指定限制试剂时，按已给量在试剂行里
      挑摩尔数最小的点名「通常它就是限制试剂」；指定了但某试剂当量 < 1 时点破
      「按摩尔数真正的限制试剂其实是它，欠量若是有意设计可忽略」。
      角色一个都不代改——替人改角色等于替人定工艺
- [x] **相态字段**（CH-4.5）：库里一个（纯品常态，CSV 认「相态/固/液/solid/liquid」，
      认不出的照实报不猜）、配料行一个（**这一炉以什么形态投料**——苯甲酸配成乙醇溶液
      泵进去就是「液」，行上的不被库里的盖掉）。「未填」是合法状态：不知道就不填，
      校验对没填的不拦也不从熔点瞎猜——猜错一次拦一炉好工艺，代价不对等。
      自带十条种子全标「固」（照实，熔点最低的布洛芬也有 76 ℃）
- [x] **固体不走泵**（CH-4.5，Error 真阻断）：相态标「固」的配料行接到泵加料步骤，
      校验条红字拦下并给出两条后路（改「液」/ 改用「消息提示」提醒人工投料）
- [x] **沸点阻断**（CH-5.1，Error）：加料步骤执行时的估算釜温（排期温度链，
      循环多轮取最热的那轮）超过该行沸点——往热釜里泵低沸点液体会闪蒸喷溅。
      沸点 / 熔点连库时随快照拷进行里，**启动闸不吃活库也拦得住**；没有数据不拦不猜
- [x] **熔点警告**（CH-5.2，Warning 放行）：配方最低温度（各步开始温度 ∪ 控温目标，
      含梯度分段）低于某**液体**组分的熔点——冰乙酸 16.6 ℃，降到 10 ℃ 就在釜里凝住。
      只查液体投料的行（标「液」的，或没标但按毫升量的）；固体行不查，
      「低于熔点」对固体是废话。结晶正是设计意图的场合，看一眼忽略即可
- [x] **釜容 80 % 经验红线**（CH-5.6，Warning）：配料合计与配方累计加料两处都查，
      占到八成就提醒「留出搅拌与放热的余量」；超 100 % 仍是原来的 Error 阻断，
      两条不重复出现
- [x] 合计：投料质量、合计体积、跟釜容对一下。
      合计体积写明是**各组分体积相加的估计值**，混合后实际体积会有出入——不摆成实测值
- [x] 表一级的毛病也说：没有限制试剂、有两个、限制试剂拿当量当基准（循环定义）
- [x] **接进加料步骤——引用链**（CH-4.1 / 4.2）：凭据先是引用（配料行 Id），再是名字。
  - 建立引用的两条路：步骤属性里的「连配料表」下拉选一行；或配料表页按
    「应用到加料步骤」（对上的步骤成批建立引用 + 填体积）。老配方没建过引用的
    按名字对——存量配方不能一夜全断
  - **引用了就跟随**：配料表一变，linked 步骤的体积自动同步（全部通道都查），
    走快照 + 系统日志留痕，配方页撤销拉得回来。步骤里始终存显式数值——
    下发执行的那个数必须明晃晃躺在步骤里，绝不做「运行时才去配料表取数」
  - **手改体积即脱离**：跟随标志清掉，引用还在；状态行变琥珀「已脱离计算」，
    校验条说清「手填 X mL，配料表算出 Y mL，要恢复跟随按『应用到加料步骤』」。
    「明确的动作」从每次同步收缩成建立引用这一次——之后的跟随是引用语义本身，
    不再是「有人在操作人没看的时候改了工艺」
  - 建了引用**改组分名不断**；引用的行被删了就是断了（红字 + charge-refgone），
    **不退回按名对**——那可能悄悄对上一个恰好同名的新行，比明说「断了」危险
  - 对不上（查无此名）、跟随未同步（转瞬即逝，打开配料表页即追平）、已脱离、
    算不出体积——各自一条校验，文案分开，不混成一句「不一致」
  - 算不出体积的行**不去覆盖**配方里人填的那个数
  - 步骤属性有一行连接状态：绿 = 跟随中、琥珀 = 脱离 / 仅按名字、红 = 引用断了
- [x] **启动那一刻冻进运行记录**（基线的一部分）：跑起来之后再改配料表，改的是下一炉；
      「用的是哪一批、按什么当量投的」正是 GLP 要问的
- [x] 报告里一节「配料表与化学计量」，一路一张表 + 表脚写清限制试剂 / 合计 / 理论产量与

      一路都没有配料表就整节不出现——硬摆一张空表，读报告的人会以为这一炉什么都没投

- [x] 报告章号改成**按实际排进去的节数往下数**。从前每处写死，取消掉「步骤执行记录」

- [x] **饱和温度**（原型 FR-5.9 那颗按钮）：拿这一炉的浓度（溶质应称量 ÷ 溶剂体积）
      在库里那条溶解度曲线上解出饱和温度，可以带余量直接写进控温步骤的目标温度。
      降温结晶的整套参数就是从这个数起的：溶清温度设在它上面几度，结晶终点设在它下面
  - **曲线是水里的（g/100 mL 水），溶剂不是水就拒绝换算**。拿水的曲线去算甲苯体系，
    会得到一个看着非常合理的错温度，而没人查得出来——这是这件事最要紧的一条
  - 认水按精确匹配 + CAS，不做包含匹配：「水杨酸」「水合肼」里都有个水字
  - 浓度超出拟合区间（0 ~ 90 ℃）照实说「全溶，没有饱和点」或者「90 ℃ 也溶不完」，
    不外插——外插出去的值不是数据，是二次函数的想象
  - 曲线不单调（先升后降的体系是有的）就说给不出唯一解，不在两个根里挑一个
  - 解法用二分不用求根公式：求根要在两个根里挑，挑错了就是一个「在区间内、看着也合理」
    的错温度
  - 写入是一次明确的动作，改了哪一步、从多少改到多少都说出来，配方页撤销得回去
  - 化合物库页那颗从前的死按钮（没有 Command，底下还配着一句「可自动引用…」的承诺）
    改成把人带到配料表——浓度只有那一页才知道
- [x] **每 1 g 目标产物需要多少限制试剂**（只读的一行换算）。
      **放大批量本来就只是改限制试剂那一格的数**——整张表都是相对它算的，改完全表跟着走；
      这个数只是省一次除法。**没有做成「放大批量」按钮**：传热面积与体积之比、搅拌雷诺数、
      加料时长、放热速率都不随批量线性缩放，一颗那样的按钮会暗示放大这件事做完了
- [x] **从运行记录回填实取**：泵的累计加料量（`volume` 标签）一直在采、也进了归档，
      实投从前却只能人手抄。计划与实际在物料这一侧本来就能闭环，缺的只是接上
  - 读的是采样不是步骤记录里那句「实加 12.40 mL」：那是给人看的话，措辞一改就悄悄失灵；
    采样是数，而且任何会发这个标签的驱动都适用，包括以后接的真机泵
  - 窗口开到**下一条加料步骤开始之前**：累计量只在加料时动，而泵的最后一次上报常常落在
    步骤结束之后那一瞬——只读到步骤结束会把尾巴丢掉（实测：计划 12 mL 只读回 8 mL）
  - 整段扫一遍查回退：累计量按驱动会话各自累加，中途重开会归零。只比两端的话，
    「0 → 8 → 重开 → 2」看起来就像老实加了 2 mL
  - 归档的早期采样被环形缓冲顶掉时照实说读不出来，不当成「从 0 开始」——
    那会算出一个大得离谱、看着却很像真的实加量
  - 同一个组分分几批加就加起来算一次；密度知道就顺带把实投克数也填上
- [x] **这一页要够安静**（真机截图上一眼看出来的三处噪声）：
  - 一行溶剂都还没有的时候，「溶解度与饱和温度」**整块不出现**。表刚填了第一行就摆出
    一块来说「没有溶剂」，那不是问题，是表还没填完——界面上一块红字会让人以为自己
    弄错了什么。例外只有一个：有一行看着就是水、只是角色没标成溶剂，那是个具体的、
    改一下就好的疏漏，点出来是帮忙
  - **按克称的固体没有密度不标红**。它的 mmol 和应称量一个不少，只是不进合计体积；
    红字要留给真挡住计算的（按毫升 / 按倍量给量却没有密度，那是连应称量都算不出来）。
    同时合计体积漏掉了谁必须说出来——不然拿它跟釜容一对，得出的「装得下」是假的
  - 这一路没有控温步骤时说一句，不摆一个空下拉在那儿让人点
- [x] 台面上没有通道时，配料表的四颗动作钮跟通道下拉一样置灰：存盘时泳道压根不存在，
      加进去的行会被悄悄丢掉
- [ ] 从配料表反推「按这个投料量，限制试剂该称多少」——**不打算做成功能**，见上面那条换算
- [ ] 多步反应：一张表只管一步，中间体接力还得人工换算
- [ ] 溶解度曲线换成能标溶剂的（现在只有水），乙醇 / 甲苯体系才算得了饱和温度

      · **缺省限值比设备工作范围松一档**（±1 ℃ / +25%）。实测撞出来的：
        设备允许 16 ℃/min，配方照 16 ℃/min 跑，噪声让实测斜率在 16 上下抖——
        限值卡死在 16，一次完全正常的升温就被判成超速并中止整批。
        联锁防的是「跑飞了」，不是「贴着上限干活」
      · 越限那个数印得出和限值的差别（「高于上限 180.0（实测 180.01）」，
        而不是「180.0（180.0）」那种看着像程序算错了的写法）；
        消息不自带通道前缀（清单和记录都有「通道」这一列，否则读成「CH1 CH1 Tr 高于上限」）
      · 台面重建时正在报的一并收尾（限值马上就没了，留着只会等一个再也不会来的恢复），
        没确认过的仍留在清单上等人确认
      · 17 条回归
- [x] **趋势图导出图片**（趋势工具条上的「导出图片」）：不是截屏——
      另排一份离屏的可视树，2× 渲染，把实验名 / 通道与孔位 / 窗口 / 时间范围 /
      采样点数 / 导出时刻与操作人一起写进去。**仿真跑出来的单独一块红底标出来**，
      绝不能和真实数据混进一份报告（§8.1）。图用的就是界面上那个控件，

- [x] **记录链上的追加是线程安全的**：往一条通道记录上追加的不止一个线程——
      执行循环在线程池上跑，安全层在自己的定时器线程上求值，手动标记与报警确认

        · 告警解除后自己回到可用，不挂着等人手动清
        · 开设备时先读一次告警字再开轮询——轮询是「先取快照后读告警」，
          不先读的话第一帧温度是在不知道有没有告警的情况下发出去的

        要用它得另写一个驱动
