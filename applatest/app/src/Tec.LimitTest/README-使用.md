# 控温极限测试工具（Tec.LimitTest）

给现场做极限测试用的独立小程序：按「最低温 / 恒温稳定性 × 冷却水 20 / 12 / 7 ℃，外加最高温一次（不用冷却水）」的
矩阵自动跑，数据直接写进「控温极限测试记录」工作簿（说明 + 7 张测试表 + 结果汇总矩阵），不用人抄。
界面从简，主要是把数据填对。控温对象可以选**夹套**（单环）或**釜内**（上位机串级）。

## 跑之前

- **串口只能一个程序占着。** 把工作站（Tec.App）和设备 HMI 关掉再开这个工具；测完再开回去。
- 台面：工具自己的数据目录是 `%AppData%\TecLimitTest\`，里面的 `bench.json` 就是台面（格式跟工作站的
  台面文件一样）。第一次开机没有的话，先从设备 HMI 的 `%AppData%\TecHmi\bench.json` 拷一份；那也没有就写一份
  缺省的（主机 + 两支宇电探头，串口按驱动缺省：RD105 COM7、IO8R COM10、两支宇电探头都是 COM3）。
  串口不对在左栏改，点「保存并连接」。也可以「导入台面…」选工作站另存的 `.tecbench`、设备 HMI 的 `bench.json`
  或实验文件 `.tec`（取里面的台面）。
- 运行：`dotnet run --project src/Tec.LimitTest`，或发布后双击 `Tec.LimitTest.exe`。
  数据目录可用环境变量 `TEC_LIMIT_DATA` 改。

## 控温方式与增益表（0325 起）

控温在哪儿闭环由台面里主机的设备配置「控温方式」定（工作站台面页的属性栏改，改完另存 `.tecbench` 导进来；
或直接改 `bench.json` 里那台主机的 `config`）：

| 控温方式 | 谁在闭环 | 釜内控温 |
|---|---|---|
| 温控器 PID | 温控器自己（TG + SPEED，出厂 3000/150/0，单环夹套） | 做不了：釜内目标也是当夹套目标下发的，这个工具选「釜内」会被驱动拒绝 |
| 上位机 PID（串级） | 上位机 `HostControlLoop`：温控器只采温、出功率（MODE=3） | 可以：外环吃宇电探头的 Tr，出内环夹套设定 |

双工位反应主机**缺省就是上位机 PID**，配套两项也有缺省：「TEC 输出反向 = 反向」「加热棒占空比 = 负」——
按现场看到的「降温 PWMDUTY +90、升温 −90」定的，**没在真机上验证过**。第一次跑先在 25 ℃ 附近开一次控温看方向：
两三分钟内停控、日志说「方向接反」，就把对应那项换一下再开。

增益表（各温度点的 PID）按台面实例 + 路 + 执行器落盘（环境变量 `TEC_GAINS_DIR` 可改目录）：
`%AppData%\TecDrivers\gains\<实例 ID>-tc<1|2>.csv` 是 TEC 那张，`…-tc<1|2>-heater.csv` 是加热棒那张，
格式都跟 TecControl.App 的 `gain-schedule.csv` 一字不差；手动参数在 `…-tc<1|2>-pid.json`。
表空着也能跑（保守缺省：内环 8 / 0.02 / 0，外环 2.5 / 0.0079 / 0），日志会提醒「先自整定」。
**看表、改表、自整定都在工作站（或设备 HMI）手动控制面板的「PID 整定」页**（0327）——这个工具开着时串口被它占着，
先关掉这个工具、在面板上按建议点位整完，再回来跑矩阵。

上位机 PID 下每次下发目标都会在 `%AppData%\TecDrivers\loops\` 记一份逐拍 CSV（0332，设定 / 内环设定 / Tr / Tj / 占空比 /
内外环 P·I·D / 热源侧，每拍一行），排查控温问题先看它。台面设备配置里「PWM 输出频率」缺省 1 Hz（加热棒交流 + 固态继电器
的功率分辨率 2 %），开会话写进温控器。

±0.01 ℃ 是目标不是承诺：能不能到看恒温表里「1 s 稳定度」那几行，整定得好不好、探头噪声、冷水机波动都在里面。

## 装到别的电脑

出包（在装了 .NET 8 SDK 的开发机上；目标电脑**不用装 .NET**）：

```bash
scripts/publish-limit-test.sh win-x64 0325      # Linux / macOS 开发机
scripts\publish-limit-test.cmd 0325             # Windows 开发机
```

最后一个参数是版本号（`.sh` 前面还有一个 RID；`.cmd` 只认 win-x64，就这一个参数），一般填打到的补丁号：
标题栏显示它，记录表「补丁版本」缺省填它。
产物在 `dist/tec-limit-test-win-x64/`：单文件 `Tec.LimitTest.exe`、几个 `.pdb`（报错时栈里带行号，留着别删）和这份 README，
顺手打成 `dist/Tec.LimitTest-win-x64-<版本号>.zip`。版本号就写四位补丁号（0325 这种），两边脚本都认。
**绝不加 `PublishTrimmed`**（Avalonia 反射绑定会被裁剪弄坏，规矩同 HMI）。

目标电脑上：

1. 整个目录拷过去（U 盘、共享都行），随便放哪，比如 `D:\TecLimitTest\`。第一次双击 exe 会解压几秒，之后就快了。
   杀毒软件拦「未知发布者」就放行——没有签名，是自己出的包。
2. 装 USB 转串驱动（现场那台是 CH344，四口）。装完在设备管理器里看 COM 号，**每台电脑的 COM 号都可能不一样**。
3. 打开工具，左栏把 RD105 / IO8R / 宇电的串口改成这台电脑上的 COM 号，点「保存并连接」。
   改过的台面存在 `%AppData%\TecLimitTest\bench.json`，下次开机还在；也可以「导入台面…」直接选工作站另存的 `.tecbench`
   或另一台机器上的 `bench.json`。
   程序起不来（双击没反应）看 `%TEMP%\TecLimitTest-crash.log`。
4. 测完把这四样带回来：`我的文档\控温极限测试\` 里的 `.xlsx` 和 `csv\`，`%AppData%\TecLimitTest\Logs\` 里的日志，
   `%AppData%\TecDrivers\gains\` 里的增益表（整定的结果在这儿）。

Linux 目标机：RID 用 `linux-x64` / `linux-arm64`，运行账号要进 `dialout` 组，要装中文字体（`fonts-noto-cjk`），串口名形如 `/dev/ttyUSB0`；细节同 `src/Tec.Hmi/README-部署.md`。

## 界面怎么用

1. 左栏填串口，点「保存并连接」。顶上写「已连接：双工位反应主机（R1）· CH1 / CH2」才算连上
   （名字来自台面里那台主机的标签）；哪台设备没开起来，它下面的状态会写原因。
2. 矩阵上方选「控温对象」：**夹套 Tj（单环）** 或 **釜内 Tr（串级）**。选釜内的条件：台面里「控温方式」是上位机 PID，
   而且两个工位的釜内 Tr 此刻都有读数——缺一样「开始」就拒绝并说清哪一路没有。
3. 「冷却水温度」填一串（逗号分开，缺省 `20, 12, 7`），顺序就是跑的顺序；低于 7 ℃ 拒绝（冷水机的下限）。改了矩阵跟着重排。
4. 填测试条件：操作人、环境温度（手填）、补丁版本、输出目录（缺省 我的文档\控温极限测试）。
5. 参数缺省 −40 / 150 / 25 ℃，60 / 60 / 120 min，稳定度窗口 30 min，都可以改。目标超出温控器超温上下限会拒绝开始。
6. 矩阵里勾要跑的格：每个水温下「最低温 → 恒温」串着跑，两项之间先回到 25 ℃ 附近（回温一律控夹套）；
   最后一格「最高温 · 无冷却水（只测一次）」放最后跑，跑完不回温、自然冷却。
7. 点「开始」。工具停在「请把冷却水调到 20 ℃…」：把冷水机调好、等水稳，把冷水机上看到的实际水温填进去，点「继续」。
   这一组不做就点「跳过当前」。每换一个水温都会停下来问一次。轮到最高温时提示是「把冷水机停了，点继续」——不要水温。
8. 中途：「跳过当前」跳过正在跑的那一格；「停止」结束整轮（当前那格记中止）；「急停」设备所有输出收安全态。

## 每一项怎么跑

| 项 | 做法 | 什么时候结束 |
|---|---|---|
| 最低温（每个水温一次） | 两工位同时「尽快」下发目标（缺省 −40 ℃），控夹套还是控釜内按「控温对象」 | 跑满时长；或最近 10 min 两工位被控量变化都不到 0.2 ℃（提前结束，可关） |
| 恒温稳定性（每个水温一次） | 下发目标（缺省 25 ℃），等两工位被控量都进 ±0.5 ℃（到达用时进表），再记录 2 h | 记录满时长；90 min 没到目标算中止 |
| 最高温（只一次，不用冷却水） | 同最低温，目标缺省 150 ℃；「切到电加热的时刻」从热源状态量的跳变记 | 同最低温；跑完不回温 |

中止的情况：操作人停止 / 跳过 / 急停；安全层触发（Tr 越限、设备告警字、信号丢失）；回路自己停控（跑飞 / 方向接反 /
釜内 Tr 丢失，原话在日志）；两工位夹套连着 30 s 没读数；控釜内时两工位釜内 Tr 连着 30 s 没读数；夹套跑出设备范围 2 ℃ 以外；
驱动拒绝下发（釜内没有 Tr 之类，原话进表，整轮停）。原因写进那张表的「结果」格，之前写的行都在。

## 数据从哪来、哪些是手填的

- 夹套温度 / 输出 / 热源 / TEC 功率线：驱动每秒采样，取记录点那一刻的值（最低温 / 最高温每 1 min 一行，恒温每 2 min）。
- 釜内温度：宇电探头会话发的 Tr；没接探头这一列就是空的。
- 电流：上位机 PID 下会话每两秒发一路 `cur`；温控器 PID 下从「实时状态」组每 5 s 读一次。
- LIMITED、超温上限：开始每一格时从温控器读；电加热切换阈值、热源死区：从台面配置读。
- 恒温「1 s 稳定度」几格（窗口分钟数、Tj / Tr 峰峰值、标准差、被控量平均与目标差）：工具用记录段最后 N min 的每秒数据算好
  填进汇总块——Excel 里没有每秒数据，2 min 一行那份只是抽样。**看 ±0.01 就看这几行**，结果汇总也拉过去了。
- **手填的只有三样**：操作人、环境温度、冷却水温度（不是测的，工具问你，你填冷水机上看到的数）。
- 没采到的格子留空，工具不编数。每秒的全量数据在输出目录的 `csv\` 里，一次测试一个文件（最高温那份名字带 `nowater`）。
- 记录表每到一个记录点保存一次；`结果汇总` 那张全是公式，Excel 打开时算。
