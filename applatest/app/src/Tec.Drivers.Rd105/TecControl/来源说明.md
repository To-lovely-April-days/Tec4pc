# 这个目录是拷贝，不是原件

原件在仓库根部的 `src/TecControl.Core`（`TecStudio.sln` 里那个工程）。
这里是**按文件拷过来的一份**，跟着 `Tec.Drivers.Rd105` 一起编译，
命名空间原样保留 `TecControl.Core.*`，所以拷过来一行没改。

## 为什么拷而不是引用

引用要么把 `TecControl.Core` 也登记进 `app/Tec.Studio.sln`（VS 的还原只认解决方案
里列着的项目，不登记就报 NU1105），要么让 `app/` 去依赖解决方案之外的路径。
两条都会把两个解决方案绑在一起——`app/` 从第一天起就是跟根目录完全隔离的，
不该为了一个驱动破例。拷一份换来的是 `app/` 自己编得起来、自己测得过。

以及 `Control/` 里控制环真正用得上的那 10 个，外加 0325 补拷的 `Control/GainScheduleStore.cs`
（原样一行没改：上位机 PID 的增益表落盘，`Rd105HostControl` 用它读写 `%AppData%\TecDrivers\gains\<实例>-tc<n>.csv`，
格式跟 TecControl.App 的 `gain-schedule.csv` 一字不差，那边整定过的表拷过来就能用——这正是拷它而不是另写一份的理由）。

|---|---|

下次同步时如果控制环开始用它们了，补进来即可。

## 本地改动（重新同步时要再打上）

三处。前两处跟控制算法无关；第三处（`HostControlLoop`）动的是回路的**结构**（几路、被控量从哪来、什么时候不写），
PID / 增益表 / 前馈 / 自整定 / 跑飞检测的算法本身一行没改：

| 文件 | 改了什么 | 为什么 |
|---|---|---|
| `Control/HostControlLoop.cs`（`【本地改动】` 标记 21 处） | ① `ChannelSyncMode.Independent`：两路各有各的回路 / 设定 / 停控（`WriteDuty` / `PrepareOutput` / `StopChannel` 不再连带 ch2）；② `SetOuterSource(ch, Func<double>)`：串级外环的被控量可来自外部，读不到（NaN）按路触发停控并说明；③ `SuspendOutput(ch, bool)` / `IsSuspended`：挂起期间不算不写不重写手动输出，恢复时重置周期计时；④ `SetHeaterSign(ch, ±1)`：只加热执行器写到设备上的占空比符号按接线定，反向对它无意义；`LastDutyPercent` 记 PID 那一侧的量（≥0）；⑤ `event ChannelTripped(ch, reason)`：`TripChannelAsync` / `TripSafetyAsync` 按路发；⑥ `ManagePwmFrequency`：可以不动设备全局 FPWM；⑦ `SetManualGains`：只换手动增益不动上限与方向；⑧ `SetActuatorMode` 在挂起状态下允许换形态（换了就 PID 复位、前馈预置、跑飞检测重开） | 源工程是单釜：一台 RD105 两路一块动、外环吃本机 TC、执行器形态开机定死、FPWM 按形态改。双工位主机是两路各控一个工位、釜内 Tr 由宇电模块另采、热源切换由程序扳继电器（切换那两秒输出必须挂起）、加热棒是接在某个引脚上的 PWM SSR、FPWM 两路共用一个设备全局值不能由一路改。这些都是「回路放在什么机器上」的事，算法不变 |
| `TecController.cs` `ReadSnapshotAsync` | DATADEMAND 应答里 `TCn:OUTV` 与 `TCn:RESISTOR` 可缺，缺了读成 NaN（原来缺字段直接抛）；`TCn:TCADJTEMP` 照旧必须有 | 现场 RD105 走 RS485 口 = Modbus-RTU；寄存器表里没有「实际输出电压」，电阻有的固件答不出来（按参数长度答，不按请求个数答），`Rd105ModbusBridge` 都不编一个值出来。驱动没有消费 `OutVolts` / `Resistor` |
| `Comm/SerialPortTransport.cs` | `Open()` 碰到 Win32 错误 1「函数不正确」就扔掉旧 SerialPort 换新的再试一次；`Dispose()` 里 Close 抛了也照样 Dispose；加 `PortName`；加 `Reopen()`（扔掉旧 SerialPort 换新的开，旧句柄 Dispose 抛了也照扔） | 现场宇电模块断电重上电时 USB 转串跟着掉了一下，程序里口子还开着，再开 COM8 报「函数不正确」。第二次开多数能过；不过的由 `SerialFault.Explain` 翻成「把 USB 转串重新拔插一下」。`Reopen()` 给 `Tec.Drivers.Rd105.LinkRecovery` 用：轮询中途口子死了（降温跑到 48 min 突然每拍都报错）自己关掉重开，不用重启程序 |

改动处有 `【本地改动】` 标记，同步时 grep 一下。
