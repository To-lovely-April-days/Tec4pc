# 分程加热（>100℃ PWM 电加热）设计备忘

> 状态：**手动换线过渡版已实现**（2026-08-03）：DAM-3028D 到货前由人工换接线，
> 软件提供"电加热棒（只加热）"执行器模式（见文末第七节）。DAM 自动路由版仍待硬件到货。
> 本文汇总电气图纸（TEC_ControlSystem.pdf）、RD105 协议 v1.3.0 与厂家技术支持问答的全部结论。

## 一、系统构成（双釜，每釜一套）

- **TEC215**：TEC1±/TEC2± 驱动两组 TEC；Sensor1=Pt-1000 釜内（外环）、Sensor2=Pt-100 炉内（内环）；
  PWM2 引脚经固态继电器（美格尔 MGR-1 X4810，过零型）通断 220V 市电给加热棒；
  另有辅助加热棒（继电器直接通断，无 PWM，升温助推用）。
- **DAM-3028D**（阿尔泰，RS485/Modbus RTU）做全部路由开关：
  OUT0/1=K1/K2 加热棒市电总闸；OUT2/3=K3/K4 温控器使能（ENABLE 引脚）；
  OUT4/5=K5/K6 辅助加热棒；OUT6/7=K7/K8 TEC 功率线通断（JQX-30F-1Z 30A）。
  输入：IN0/1=水流开关（冷却水联锁）；IN6/7=温控器 STATE（到温指示）。
- **KHTH-PT100-2**（RS485）：独立保护测温链（每釜一支保护 Pt-100）。

## 二、厂家确认的固件事实（2026-08-03 技术支持陈工）

1. 每通道一对分程引脚：**PWM1/PWM2 = 通道 1 的制冷/加热，PWM3/PWM4 = 通道 2 同理**。
   占空比为正走加热脚、为负走制冷脚，方向路由固件自动完成。
2. PWM 引脚占空比 = 该通道 `PWMDUTY`，**无独立指令**（"PWM 口和 TEC 口是同步的"）。
   上位机指令路径与现有 TEC 控制完全相同。
3. **`ENABLE=0` 时 PWM 引脚不输出** → 加热时使能必须保持打开，电气隔离靠 K7 断 TEC 功率线；
   K3 的角色 = 硬件总闸/急停（断开则 TEC 与加热 PWM 全停）。
4. `FPWM`（0x000D）：0=0.5Hz / 1=1Hz / 2=10Hz(默认) / 3=100Hz。
   配过零型 SSR 必须设 **0**（2s 周期，50Hz 市电下 0.5% 调功分辨率；默认 10Hz 只有 10%）。
5. `POWERMODE=2`：断电再上电默认不输出（重启安全），两通道都要设。
6. **没有通信看门狗：通信中断后输出保持最后占空比，一直输出。**
   旧认知"MODE=3 约 1 分钟撤销输出"作废；设备内过温保护是唯一不依赖通信的兜底。
   （教程中"连续通信失败→输出已归零"的表述基于旧认知，恢复开发时需更正。）
7. 协议对高温无障碍：TG 范围 −400~1000℃，过温阈值到 5000℃；485 出厂 9600 需改 38400；
   `CHRATIO`（固件制冷/制热系数）保持出厂 1.00，不对称补偿统一在上位机做，防止双重补偿；
   STATE 引脚 = 到温指示（STEADYIOB 条件）。

## 三、运行状态表

| 状态 | K1 加热棒市电 | K3 使能 | K7 TEC线 | 占空比 |
|---|---|---|---|---|
| TEC 态（<100℃ 全程 + 高温段降温） | **断（硬规则）** | 合 | 合 | 双向 |
| 电加热态（>100℃ 加热） | 合 | 合 | 断 | 只给正 |
| 急停/安全态 | 断 | 断 | 断 | — |

**TEC 态 K1 必须断**：占空比为正时 PWM2 脚总在发波（<100℃ TEC 加热时同样如此），
K1 合上加热棒会跟着 TEC 一起加热。这是硬性联锁，不是保险。

## 四、安全防线（四层）

| 层 | 机制 | 依赖 | 状态 |
|---|---|---|---|
| 0 | TEC215 内置过温保护触发停输出 | 只依赖设备 | **待确认过温触发是否连 PWM 引脚一起停** |
| 1 | 上位机经 DAM 断 K1（与 TEC215 串口是两条独立通路） | 上位机存活 | 恢复开发时实现 |
| 2 | DAM 自身通信看门狗：主机死 → 继电器全释放 → 安全态 | 只依赖 DAM | **行动项：查 DAM-3028D 手册确认有无此功能** |
| 3 | 加热棒回路串机械温控器/热熔断器 | 纯硬件 | **行动项：建议硬件增加** |

## 五、待厂家确认（最后三条，均为电气/安全问题，与软件无关）

1. 传感器过温保护（OVERTTEMP=1）触发时，PWM 引脚输出是否一起停？（第 0 层防线是否存在）
2. TEC 输出线开路（加热态 TEC1± 空载）长期驱动，设备会否报错/受损？（K7 断线隔离方案的前提）
3. PWM 引脚输出电平/最大驱动电流？可否直推 MGR-1 X4810（输入 3~32VDC）？（决定要不要加光耦）

## 六、DAM 自动路由版的软件工作清单（待硬件到货）

1. DAM-3028D Modbus RTU 驱动（独立串口）；
2. 三态模式状态机：TEC 态 ⇄ 电加热态 ⇄ 安全态，先断后通时序 + 切换防抖
   （需求反向超幅值且持续数秒才切，切后最短驻留；高温段稳态应整体驻留电加热态）；
3. 软件心跳绑定 K1 的看门狗逻辑（心跳停 → K1 释放）；
4. 水流开关联锁（TEC 态前置条件）、辅助加热棒投切逻辑（远离目标投入、接近提前退出）、
   KHTH-PT100-2 读取与第二路超温判据。

## 七、手动换线过渡版（已实现，2026-08-03）

DAM 到货前由人工换接线，一次运行内执行器固定。软件改动：

- `ActuatorMode`（Bidirectional / HeatOnly）：界面"电加热棒模式"勾选框，
  运行/整定中禁止切换（形态必须与实际接线一致）；
- HeatOnly 下内环 PID 输出限 [0, 上限]：贴 0 不积负积分（条件积分对下限同样生效）、
  串级内环"贴 0 也算饱和"冻结外环积分、跑飞保护只看加热侧、反向输出忽略、
  手动输出拒绝负值；
- 每次启动自动下发（幂等）：POWERMODE=2 双通道（断电重启不输出——固件无看门狗，
  出厂 POWERMODE=0 会带旧占空比复活）；FPWM 按执行器形态写（HeatOnly=0 档 0.5Hz
  时间比例，Bidirectional=2 档 10Hz），防止加热棒会话把 0.5Hz 残留给 TEC 运行；
- 继电自整定支持输出下限 0：摆动整体落在正半轴，弱加热半周靠自然散热；
  幅值应 ≤ 上限一半（可行偏置域为空时整定器自动收缩到量程中点）；
- 增益表 100℃ 分段 + 加热比列此前已就位；
- 教程新增换线清单、调参流程与安全须知；"通信失败输出已归零"表述已更正。

测试 147/147（新增：PID 只加热限幅无负积分、只加热继电整定全程非负 + 自寻中）。

复查修复（2026-08-03 第二轮）：

1. **稳态前馈模型补 100℃ 分段**——原实现把所有稳态点拟合成一条直线，加热棒的
   稳态输出（另一套执行器的量纲）会混进 TEC 段的拟合把两段预测都拉歪；
   现学习/预测均不跨段，与增益表同规则；
2. **只加热模式加热比恒 1**——单向执行器无对侧可配平，整定测得的就是加热棒增益，
   再除全局比值（多为 TEC 时代的 2.0）会让闭环增益与整定失配砍半；
3. 整定器输出上下都按边界截（幅值过大导致偏置域塌缩时不再越过用户上限）；
4. 只加热模式跑飞保护提示改为加热棒故障排查项；界面积分预置/前馈提示的
   反向换算在只加热模式下跳过。
