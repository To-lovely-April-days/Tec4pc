# TecStudio 现场调试教程（按步骤执行）

适用：光测未来双通道 TEC 温控器 + TecStudio 上位机（上位机 PID 控温版）。

> **结构更新（实机确认后，以本节为准）**：
> 执行器 = 4 片 TEC 制冷（两路输出各接两片，设备 CONTMODE=2 使通道 2 硬件跟随通道 1，
> 四片同进退）+ PWM 引脚驱动的电加热膜；传感器 TC1 在**内部**、TC2 贴**腔体壁**。
> 软件为**单主控制环**（通道 1 主控，通道 2 纯监视），反馈传感器界面可选（快环推荐 TC2 腔体）。
> 下文涉及"两通道各自整定"的旧表述以此为准折算成单环操作；占空比符号与制冷/加热
> 路径的对应关系需先做 **+5% 手动实验**确认（见第 3 步，方向若反用"反向输出"勾选对齐）。

> **安全总则**：首次上功率调试必须有人在场；硬件保护参数（第 2 步）设好之前不要给 TEC 上大功率；
> 程序在停止控温/断开/关窗/通信中断时会自动把输出归零，但设备端的硬件保护才是最后防线。

---

## 第 0 步：准备工作（办公室完成，不用设备也能做）

1. 一台 Windows 电脑，安装 [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0)；
2. 解压 `TecStudio.zip`，用 Visual Studio 2022 打开 `TecStudio.sln`（或命令行 `dotnet build TecStudio.sln`），
   首次编译需联网还原 NuGet 包；
3. 编译产物：`src/TecControl.App/bin/.../TecStudio.exe`，双击能打开界面即可；
4. 硬件检查清单：
   - 设备 24V 供电接好（V+/V-，注意极性）；
   - TC1 探头贴在腔体、TC2 探头贴在腔体外层，接入对应传感器端子并压紧；
   - 两片 TEC 分别接通道 1、通道 2 输出端子，记下接线极性；
   - TYPE-C 线连电脑（TTL 波特率 38400）；
   - **建议：第 1 步之前先不给 TEC 负载电源上电**（只给设备 24V），先安全地打通通信。

---

## 第 1 步：打通通信（不带功率）

1. 设备上电，电脑插 TYPE-C，在"设备管理器 → 端口"里确认出现 COM 口；
2. 打开 TecStudio → 点"刷新" → 选中该 COM 口 → 波特率保持 38400 → 点"连接"。

**应该看到**：
- 状态栏显示"已连接 COMx（38400,N,8,1）……"；
- 顶部显示"型号代码 xx / 固件 vX.X.X"；
- 两个通道面板出现温度读数（大致等于室温），曲线区开始走线；机内温度有显示。

**不对怎么办**：
- 连接失败/无应答 → 关掉厂家 TSC 工具等占用串口的程序；确认波特率 38400；换根线；
- 某通道显示"未接传感器" → 该路 NTC 没接好或断线，检查端子；
- 温度明显不对（差几度）→ 确认设备里配置的传感器参数（R0/B 值）与实际探头一致（用厂家工具核对）；
- 状态栏提示 CONTMODE≠0 → 用厂家工具把温控器模式改回 0（各通道独立），本方案必须为 0。

---

## 第 2 步：设置硬件保护（必做，这是兜底）

对**每个通道**的"设备硬件保护"区：

1. 点"读取"，看当前值；
2. 按下面建议改后点"写入"：

| 参数 | 首次调试建议值 | 说明 |
|---|---|---|
| 占空比上限% (LIMITED) | 40~50 | 设备硬件层限幅，之后确认无异常可放宽 |
| 限流 A (SETCURRENT) | TEC 额定电流的 50~70% | 看你 TEC 片的规格书 |
| 过温上限 ℃ | 最高工作温度 +5~10℃ | 超过即断输出 |
| 过温下限 ℃ | 最低工作温度 −5~10℃ | 低于即断输出 |

**验证**：写入后再点"读取"，确认数值写进去了。

---

## 第 3 步：开环验证输出方向（关键！两通道都要做）

现在给 TEC 负载电源上电。这一步确认"正输出=加热"的方向假设对不对。

对**通道 2（腔体外）**：

1. 顶部点"开始记录"（CSV 会存到"我的文档"，文件名含时间戳）；
2. 在"手动输出"里填 `10` → 点"手动写入"（即 +10% 功率）；
3. 盯着 TC2 温度和曲线看 1~2 分钟。

**判断**：
- 温度**上升** → 方向正确，什么都不用动；
- 温度**下降** → TEC 极性与假设相反：勾选该通道"**反向输出**"，再手动输出 +10% 验证变为升温；
- 温度**没反应** → 检查：该通道负载电源是否上电、TEC 接线、告警栏是否报限流/欠压。

4. 手动输出填 `0` 写入（或点"停止控温"），结束本通道测试；
5. **通道 1（腔体）重复同样操作**。

顺便记录：+10% 时温度爬升速率大概多少（℃/分钟）——心里对对象快慢有数，
后面自整定要振荡 4~5 个周期，对象越慢整定时间越长，属正常。

---

## 第 4 步：外层（通道 2）自整定 → 启动控温

> 顺序原则：**先外层、后内层**。内层必须在外层稳定的环境里整定才准。

1. 确认 CSV 记录仍在进行；
2. 通道 2 面板：目标温度填工艺要求值（注意要在当前散热条件下可达）；
3. "PID 自整定"区：继电幅值 30%、回差 0.05℃（默认即可）→ 点"**开始自整定**"。

**应该看到**：
- 输出占空比曲线在 +30%/−30% 之间来回跳；
- 温度先爬向设定值，然后绕着设定值小幅振荡；
- 面板显示"自整定中：已完成 n 个振荡周期（一般需 4 个）"；
- 几分钟到几十分钟后（取决于对象快慢）弹窗显示结果：Ku、Tu、两套参数；
  **平稳型参数已自动填入 Kp/Ki/Kd 并生效**。

4. 弹窗确认后 → 点"**启动控温**"；
5. 观察：温度平稳收敛到设定值，输出占空比逐渐稳定到一个基本恒定的值附近。

**不对怎么办**：
- 一直停在"等待温度穿越设定值" → ±30% 推不到设定温度：加大继电幅值（如 50%），
  或确认设定值合理（不能超过 环境温度 ± 幅值×对象增益 的可达范围）；60 分钟超时会自动归零终止；
- 报"振荡不稳定" → 按提示：加大继电幅值（激励更强）或加大回差（抗噪声），重试；
- 振荡幅度太大不能接受 → 减小继电幅值（结果精度会略降，通常仍够用）。

---

## 第 5 步：内层（通道 1）自整定 → 启动控温

**等外层稳定后**（通道 2 温度基本不动、输出平稳），对通道 1 重复第 4 步全部操作：

1. 目标温度填腔体工艺值；
2. 开始自整定 → 等弹窗 → 启动控温；
3. 观察 TC1 收敛。

到这里，两路都在闭环运行。

---

## 第 6 步：稳定性验收（±0.1℃ 的验证方法）

1. 两路控温运行状态下，CSV 连续记录 **至少 1 小时**（最好覆盖空调启停、人员走动等扰动时段）;
2. 用 Excel 打开 CSV，取稳态段（收敛完成之后）的"腔体温度TC1"列：
   - 计算 `最大值 − 最小值`（峰峰值）；
   - **峰峰值 ≤ 0.2℃（即 ±0.1℃）为合格**；顺便看均值与设定值的偏差。

**不达标的排查顺序**：
1. 看 TC2：外层自己稳不稳？外层波动会直接传给内层 → 先解决外层（重整定或减小 Ki）；
2. 看通道 1 占空比曲线：
   - 周期性大幅摆动 → 参数偏激进：Kp、Ki 各减 30~50%，或直接用平稳型参数（如果当时选了快速型）；
   - 缓慢漂移跟着环境走 → 外层隔热/风道问题，检查腔体密封、风扇气流是否直吹探头；
3. 波动周期很快且幅度小（±0.02~0.05）→ 已接近噪声极限，属正常；
4. 响应太慢（收敛要很久）→ 换用弹窗里的"快速型"参数试一次，观察超调是否可接受。

> 注意：±0.1℃ 指**稳定度**。若要求对标准温度计的**绝对准确度**也到 ±0.1℃，
> 还需按协议附录 1 做多项式标定（A0~A7 系数，用标准温度计采点拟合）。

---

## 第 6.5 步：把稳定度从 ±0.1℃ 收到 ±0.05℃

先弄清楚剩下的波动是**测量噪声**还是**真实温度在动**——这两者的处理办法完全相反。

**判断方法**（用一段稳态 CSV，Excel 即可）：

1. 对温度列做 `本行 − 上一行` 的差分，取差分列的标准差 σ_d，**高频噪声 σ ≈ σ_d / 1.414**；
2. 再对温度列做 30 秒滑动平均（500ms 周期即 60 行），看平均后的峰峰值。

| 结果 | 说明 | 该做什么 |
|---|---|---|
| 平均后峰峰值明显变小 | 主要是测量噪声 | 加大微分滤波时间常数、降低 Kd；换更稳的探头/接线 |
| 平均后峰峰值几乎不变 | 是**真实的慢漂移** | 滤波无用，要解决收敛与慢扰动（下面几条） |

> 2026-07-28 那次 59 分钟记录的实测分解（稳态段 50~59.2min，952 样本）：
> 高频噪声 σ 仅 **0.008℃**，30 秒平均后 TC2 峰峰只从 0.215 降到 0.172、TC1 从 0.143 降到 0.105。
> 结论很清楚：**波动不是噪声，是系统还没收敛**（TC1 末 5 分钟仍以 +0.014℃/min 在漂）。
> 探头本身的噪声底噪只有 ±0.02℃ 量级，离 ±0.05℃ 还有很大余量——目标可行，问题在收敛。

**慢漂移的处理顺序**：

1. **先让它真正收敛再评稳定度**。判据改成"进入 ±0.05℃ 后连续 30 分钟不出带"，
   而不是"第一次碰到设定值"。没收敛就统计稳定度，量的是暂态尾巴不是稳定度。
2. **串级参数**（Tr 模式最关键的一项，见下表）。
3. **环境慢扰动**：空调周期、日照、人员走动。把记录拉长到 2 小时，看波动周期是不是
   和空调周期一致；是的话优先做保温，控制上再怎么调也只是跟着补。
4. **确认偏置限幅够用**：如果内部温度稳定停在离设定值零点几度的地方不动，而占空比
   并没有满幅——那是外环偏置顶在限幅上了。新版会自动放宽并弹提示，看到提示即可确认。

### 串级外环参数怎么给（不用现场试凑）

在辨识出的对象模型上扫了 180 组参数，结论：

| 外环参数 | 进入 ±0.05℃ | 下冲 |
|---|---|---|
| Kp 1.5 / Ki 0.0025 / 偏置 ±15（旧默认） | 75.8 min | 0.24℃ |
| Kp 1.5 / Ki 0.008 / 偏置 ±15（只加大 Ki） | 56.2 min | **1.89℃** |
| **Kp 2.5 / Ki 0.008 / 偏置 ±8（新默认）** | **37.4 min** | **0.04℃** |

两条要记住的规律：

- **下冲主要由偏置限幅决定，不是由 Ki 决定**。只把 Ki 从 0.0025 加到 0.008 而不动限幅，
  到温确实快了，下冲反而从 0.24℃ 恶化到 1.89℃。要加 Ki 就必须同时收窄限幅。
- **偏置限幅又不能收得太狠**：维持低温所需的"腔体−内部"温差正比于与环境的温差，
  −10℃ 约需 5℃，−40℃ 就要 9℃ 以上。限幅小于它，温度永远差一截到不了。
  这也是限幅必须随温度走、不能全温域一个值的原因。

程序里这几件事已经自动化，正常不用手填：

1. 自整定成功后，按该温度的 Tu 自动推荐外环参数（Kp 2.5、Ti = 1.7·Tu、偏置 ±8）并登记进增益表；
2. 运行到稳态后自动学习该温度的"稳态偏置"，下次同温启动时预置外环积分（重启到温
   场景明显更平顺）。学习只在误差进入 ±0.05℃ 后才开始——缓沉暂态期学到的值偏浅
   还会干扰放电比对，实测教训；
3. 偏置顶在限幅上满 5 分钟、内环并未满幅、**且误差已停止缩小**时，自动放宽 5℃
   （最高 ±25℃）并提示。长距离降温时偏置顶限幅但温度仍在逼近——那是限幅在正常
   限速，不会触发（判据只看误差变化量，任何温度点行为一致）；
4. 连接时若表里有旧版只填了内环参数的行，按该行自己的 Tu 自动补一组外环参数；
5. **两段式积分放电**：趋近段外环积分沿途多攒的量（−10℃ 实测过零时 −3.0，稳态只
   需 −0.35）本来只能靠温度冲过头反向积分放掉——这正是串级下冲的主因（实测下冲
   面积 334 ℃·s 与 ΔI/Ki=340 吻合）。第一枪在误差缩进 1℃ 带内时放（僵尸积分会把
   腔体设定值多压两分钟，腔体来不及归位，核心到站只能继续下沉等它——实测剩余
   0.18℃ 下冲全部来自这段腔体欠账）；第二枪在过零瞬间补刀，清掉最后一段重新攒的
   小额积分。表里该温度还没有稳态偏置时首跑会有一次约 0.2~0.3℃ 的下冲，稳住后
   自动学到，之后同温启动即基本无下冲。

### 增益表存在哪、什么时候写盘

| 项目 | 说明 |
|---|---|
| 用户表 | `%AppData%\TecStudio\gain-schedule.csv`（一切以它为准） |
| 出厂表 | exe 同级 `config\gain-schedule.csv`，**用户表不存在或为空**（如点过"清空"）时作为初值导入 |
| 写盘时机 | 自整定登记新点、学到稳态偏置、限幅被自动放宽、点"应用表格"、点"清空"、断开连接 |

也就是说**每一次改动都会立刻落盘**，程序异常退出也不会丢学习成果。想备份或换机器，
直接拷这个 CSV 即可；用 Excel 打开手工改也行，改完点"重新载入"（或重连）即可生效——
"重新载入"就是从磁盘重读用户表，用户表为空时自动退回出厂表。

> 上表数字来自仿真（对象：壁面 τ≈16min / 纯滞后 48s，内部 τ≈8.6min，由实测阶跃辨识），
> 对象参数 ±50% 失配时仍单调收敛。实机请按第 6 步的方法复测确认。

### 高温段（≥100℃）：电加热棒怎么用（手动换线版）

硬件架构：**100℃ 以上加热由电加热棒承担（PWM 时间比例调功），降温仍靠 TEC**；
100℃ 以下加热制冷都走 TEC。厂家已确认的固件行为（2026-08-03）：每通道一对分程
PWM 引脚（通道 1 = PWM1 制冷 / PWM2 加热），引脚占空比就是该通道的 PWMDUTY，
正值走加热脚、负值走制冷脚；**使能关闭则 PWM 引脚也停**（"PWM 口和 TEC 口同步"）；
**固件没有通信看门狗——断线时输出保持不变**，设备端过温保护是唯一不依赖通信的兜底。

**换线清单（每次切换执行器都要做）**：

| 去电加热棒（>100℃ 加热） | 回 TEC（≤100℃ 或高温降温段） |
|---|---|
| ① 断开 TEC 功率线（TEC1±/TEC2±） | ① 断开加热棒市电 |
| ② 加热棒经过零型固态继电器接 PWM2/GND | ② 接回 TEC 功率线 |
| ③ 使能保持接通（关使能 PWM 引脚就不发波了） | ③ 使能保持接通 |
| ④ 软件勾选"电加热棒模式" | ④ 软件取消勾选 |

**软件侧（勾选"电加热棒模式"后自动处理）**：输出限 0~上限（无制冷，降温靠自然散热，
PID 贴 0 时不积负积分）；反向输出忽略；启动时自动写 FPWM=0（0.5Hz 时间比例，过零
SSR 下 0.5% 调功分辨率）与 POWERMODE=2（断电重启不输出）；回 TEC 模式启动时 FPWM
自动恢复高频档。手动输出只接受 0~100。

**调参流程（与低温段同理，但在高温段单独做）**：

- 增益表以 **100℃ 为界分成两段**，插值、就近取点、合并覆盖一律不跨段——
  99℃ 的参数不会被拿去顶 101℃，反之亦然；设定值落在没登记过点的段会回退手动参数，
  所以**首次在高温段控温前，必须先在该段自整定至少一点**（如 110℃）。
  只加热整定的继电摆动整体落在正半轴（弱加热半周靠自然散热），**幅值别超过上限的一半**；
- "**加热比**"列在只加热模式下**不生效**（恒按 1）：单向执行器没有对侧可配平，
  该段自整定测得的就是加热棒本身的增益。此列仅作用于 TEC 双向模式
  （留给未来 DAM 自动切换版在高温段跑 TEC 降温时用）。

**安全（必读）**：

1. 上高温前**先改硬件保护**：过温上限必须**双通道**改写到目标之上留 10~15℃ 余量
   （如目标 120℃ 设 135℃）。设备无通信看门狗，串口断线时加热棒会按最后占空比
   一直烧下去——**这道阈值是唯一不依赖通信的自动停车**；
2. 强烈建议加热棒回路串**机械式温控器或热熔断器**（不依赖任何电子的最后防线）；
3. 高温运行期间不要长时间离人，结束先点"停止控温"再断电。

## 第 7 步：常见问题速查表

| 现象 | 原因/处理 |
|---|---|
| 连接失败 | 串口被 TSC 等占用；波特率不是 38400；线/驱动问题 |
| 温度显示"未接传感器" | 该通道 NTC 断线/未接（设备返回 999999999） |
| 手动输出后温度没反应 | 负载电源没上电；TEC 接线断；看告警栏 |
| 温度方向反着跑 | 勾"反向输出"（见第 3 步） |
| 告警：通道 x 输出限流中 | 输出电流到达 SETCURRENT 上限：正常限流保护，必要时核对 TEC 规格调整 |
| 告警：供电电压过低/过高 | 设备供电 <7V 或 >30V，查电源 |
| 告警：传感器温度越限 | 温度超出过温上下限，设备已按保护动作，排查后处理 |
| 自整定不起振 | 幅值推不到设定值：加大继电幅值或改设定值（第 4 步） |
| 自整定报不稳定 | 加大幅值或回差后重试；确认整定期间没人为扰动（开腔门、动风扇） |
| 深冷/深热点整定 | 新版继电自动带偏置（围绕该温度稳态输出摆动，前馈模型提供）。推荐流程：先闭环控温**稳住该温度几分钟**（让前馈学到稳态输出）→ 停止 → 立即自整定，幅值 15% 即可。没稳过就整定的话偏置取不到，深冷点会"够不着"失败 |
| 控温中程序被关闭 | 程序退出时自动归零输出并关使能；重开程序重新连接即可 |
| 连续通信失败提示"安全停机" | 串口被拔/干扰：程序会**尽力发送**归零指令；若串口已完全断开指令送不到，**设备会保持最后输出**（固件无通信看门狗，厂家确认）——此时靠设备端过温阈值/限流兜底。恢复连接后先点"停止控温"再重新启动 |
| 偶发一次"指令无应答" | 大电流 PWM 环境下丢帧属正常物理现象（实测约十万条指令一次）。新版会自动重发一次补救；仅在 VS 调试器下会弹"用户未处理的异常"（调试器对 async 的误报，按 F5 继续即可，程序自身已妥善接手，直接运行 exe 无感知） |
| 偶发一次"应答缺少字段" | 应答被干扰打坏（实测现场单比特翻转：分隔符 @ 变成 P，两字段粘连）。新版对坏帧同样自动重发一次；若频繁出现，查串口线屏蔽/接地/走线是否贴近功率线 |
| 串级时内部温度停在离设定值零点几度不动 | 外环偏置顶在限幅上（占空比并未满幅）。等提示自动放宽，或直接加大"偏置±℃" |
| 串级下冲很大、久久回不来 | 偏置限幅太大（收窄到 ±8℃ 左右、Kp 2.5），或该温度还没学到稳态偏置（首跑正常有 0.2~0.3℃，稳住自动学到后消失）。增益表该温度行"稳态偏置"有值即会过零放电 |
| 到温有 0.05~0.08℃ 的一次性小下冲 | 这是腔体跟随滞后的物理残余，属正常（两分钟内收敛）。对过冲敏感的批次：用"温度曲线"末段缓坡（如 −9→−10 @0.3℃/min）实现零过冲，代价约 3 分钟 |
| 换个目标温度就不好用了 | 增益表只在一个温度建过点。在代表温度（如 +100/0/−40℃）各自整定一次 |
| 设定 ≥100℃ 后像没调过参数 | 高温段（电加热段）还没登记增益点——分段不跨界插值，低温段的点帮不上忙。先在高温段自整定一点（见"高温段：分程加热怎么调"） |
